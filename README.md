# 汐岛

汐岛是 [X 岛匿名版](https://www.nmbxd1.com/) 的第三方桌面客户端，基于 Electron、React、TypeScript 与本地 SQLite，目标平台为 Windows 10 / 11 x64 与 macOS 13+（Intel、Apple Silicon）。

> 项目处于早期开发阶段，目前实现了浏览阅读、阅读现场、图片查看、饼干管理、两端逐项订阅与预览同步；尚无安装包。

## 当前可用功能

- 左侧导航列出论坛提供的时间线与版面；版面显示版规，时间线显示说明。
- 串列表按页读取，滚动到底部时追加下一页并按串号去重。
- 串阅读：主帖与回复连续显示，接近底部时按需读取下一页；提供“开头”、“末尾”、“首条未读”、页码跳转和“刷新”。追加内容不移动当前视口。
- 每个串可在“全部”与“只看 PO”之间切换；选择按串保存，两种模式各自保存阅读位置。
- 多标签：每个标签有自己的后退／前进历史、当前版面、打开的串和分栏开关。分栏时列表与正文并排，单击列表项只更换正文，不增加后退步骤；关闭分栏时打开串会进入整页阅读并可后退回列表。
- 窄窗口：先收窄正文两侧留白，再把导航连续收窄为仍显示完整名称的紧凑栏，然后改为可展开的导航浮层，空间仍不足时暂用单栏（正文提供“返回串列表”）。正文字号与行距不随窗口改变；窗口变宽后恢复，手动关闭的分栏不会被重新打开。
- 阅读位置与已读状态，见下文“阅读位置与已读”。
- 图片：正文中的附图先显示缩略图，点击后在应用内查看、缩放和保存原图，见下文“图片”。
- 每次读取的内容会保存到本机数据库。网络读取失败时，如本机有该页的已获取内容，会显示该缓存并标明获取时间与失败原因；没有缓存时显示失败原因和重试入口。
- 串的覆盖状态：已取得的页、缺页、结束候选页，以及服务端回复计数与实际取得条数是否一致；只看 PO 的页单独统计，不计入全部回复的覆盖。
- 饼干管理（在“设置”中）：粘贴官网导出内容或原始 userhash 导入饼干，命名、重命名、移除，并分别选择浏览饼干、默认发言饼干与网页同步对象，见下文“饼干”。
- 订阅：设置受保护的 App UUID 与固定网页同步对象，切换两端列表、打开串，显式加入／取消一项订阅，或预览后逐项同步、合并旧 UUID 集合；服务端报告与回读事实分别展示，见下文“订阅”。

尚未实现：退出后恢复标签与工作区、引用预览与跳转、发言与草稿（默认发言饼干目前只保存选择）、收藏、浏览历史列表、搜索、提醒、主题设置、缓存额度与清理设置、安装与更新。

## 阅读位置与已读

- 阅读位置按发言 ID、阅读线在该发言内的相对位置和距视口顶部的偏移保存，页码只用于先读取所在页。上方内容变高（如追加上一页、窗口变窄导致重排）时，阅读线保持在同一发言的同一位置。重新打开串时回到上次位置；“开头”“末尾”“首条未读”是显式入口。
- 发言只有在汐岛窗口获得焦点、当前标签正在显示正文、且可见高度达到“发言高度与正文视口高度中较小者”的一半，并连续保持 500 毫秒后才记为已读。窗口失焦、隐藏或切换标签会取消尚未满 500 毫秒的计时，重新满足条件后从头计时；已经记下的已读不会撤销。快速滚过、后台标签、列表预览和后台读取都不会产生已读；跳到末页不会把中间未读的页记为已读，只看 PO 时只会记录看到的 PO 回复。这是阅读判定，不代表已经读懂。
- “首条未读”和“全部标为已读”只作用于本机已经取得的发言；从未读取的页属于未知范围，不会被当作已读或未读计数。
- 关注起点在首次观察到远端订阅或确认加入时建立（后续收藏、提醒也复用它），只建立一次，此后不随来源切换重置；起点之前已有的回复既不计为新回复，也不记为已读。论坛发言时间未经核实，回复属于起点哪一侧只按本机观察和“发言编号随时间递增”判断：编号不超过“开始关注时本机见过的最大发言编号”的是旧回复；如果起点之后本机看到过某个串的末尾（有回复的页及其后的空页），此后在该串出现的更大编号回复必定发表于起点之后，编号不小于它的回复（任何串）都计为新回复。两者都无法证明时保持“无法确定”，既不计为新回复也不当作已读。判断只使用正常阅读已取得的内容，不额外发起后台读取。

## 图片

- 有附图的发言在正文里有一个固定大小的缩略图位置；缩略图只在接近可见区域时才读取，读取中、成功或失败都不改变发言高度，阅读位置不受影响。缩略图失败时在旁边说明原因并提供“重试”，不会自动反复重试；缩略图失败也仍可打开原图查看。
- 点击缩略图（或用键盘聚焦后按 Enter／空格）打开原图浮层。浮层只覆盖当前串的正文，读取原图期间显示缩略图；原图失败时保留缩略图、说明原因并提供“重试”。浮层打开期间正文被遮住，不会产生已读；关闭后焦点回到原缩略图，阅读位置不变；关闭后才到达的原图结果会被丢弃。
- 浮层操作：`+`／`-` 放大／缩小，`0` 适应窗口，`1` 原始大小，方向键（按住 Shift 加大步长）或拖动移动图片，滚轮以指针位置为中心缩放，Ctrl+S（macOS 为 Cmd+S）保存原图，Esc 关闭。
- “保存原图”只在原图已取得并显示后可用：通过系统保存对话框选择位置，写入的是本机保存的原图文件本身，文件扩展名按实际编码命名（例如论坛标为 `.png`、实际为 JPEG 的图片保存为 `.jpg`）。原图未取得时不会改存缩略图；写入先生成同目录临时文件再替换，失败时不改动已有文件。
- 图片只从 `https://image.nmb.best` 读取（缩略图 `thumb/`，原图 `image/`），请求不携带任何饼干、凭据或论坛身份，不跟随重定向，单张大小与像素数有安全上限。界面只能按“某条已读取发言的缩略图／原图”请求，不能指定网址或文件路径。
- 是否为图片只按文件内容判断（JPEG、PNG、GIF、WebP 的文件头及尺寸），不看论坛扩展名或响应的 `Content-Type`；SVG 等其他内容不接受。HTML 页面（包括以图片类型返回的错误页）、非 200 状态、跳转、内容中断都显示为对应的失败原因。失败只说明服务器这次返回了什么：论坛真实删图后的响应尚未核实，界面不会据此声称图片已被删除。实际解码在界面的沙箱进程中进行，无法解码的图片单独提示，重试时重新下载。

## 饼干

- 两个导入入口分开处理：
  - “官网导出内容”接受 `{"cookie": "<userhash>", "name": "<名称>"}` 这段 JSON，或它的 Base64（标准或 URL 安全字母表，可含换行）。名称留空时使用内容中的 `name`。
    - 获取方式：登录官网后进入饼干管理，打开某块饼干的“导出”页。扫描页面上的二维码得到这段 JSON；或者复制二维码图片地址，取 `text=` 参数的值，即其 Base64。
    - 这一格式依据参考客户端源码（见文末致谢）。已用一份真实导出的图片地址 Base64 在 Windows 上实测：导入、加密保存、重新启动后解密均成功。扫码得到的 JSON 形式尚未用真实样本验证；若粘贴的值仍带百分号编码（如 `%2B`），会被判为格式无法识别。
  - “原始 userhash”接受 userhash 值，可带 `userhash=` 前缀，必须填写名称。
- 导入成功只表示格式可接受并已加密保存，不表示论坛当前接受这块饼干；汐岛不登录、不领取、不导出饼干，也不读取浏览器中的 Cookie。
- 只接受可以安全放入 Cookie 头的字符（不含空格、分号、逗号、引号、反斜杠和控制字符），超长输入直接拒绝。错误提示按类别显示（为空、过长、不是 Base64 或 JSON、缺少 `cookie`、字符不可用），不会回显粘贴的内容。
- 再次导入已存在的 userhash（无论来自哪个入口）只提示已有条目，不修改其名称或任何用途选择。
- 浏览饼干、默认发言饼干、网页同步对象分别保存，修改其中一项不影响另外两项。
- 移除饼干会删除其密文；正在使用它的用途显示为“已移除，需要重新选择”，不会自动改用其他饼干。浏览饼干处于这种状态时，读取不会发出（也不会改为不带饼干发出），界面提示到设置中重新选择；如本机有缓存则显示缓存并说明原因。
- 读取失败（网络、权限、限流等）不会把饼干标记为失效。
- 本机数据库无法打开时，已保存的饼干与用途选择都无法读取：设置中显示饼干信息读取失败；由于无法确定浏览饼干，读取不会发出（不会当作“不使用饼干”），界面显示对应原因。

## 订阅

- 在设置中粘贴已有的 App UUID，或明确点击生成新的 UUID；首次启动不自行生成。输入默认遮蔽，保存后清空，界面只显示本机引用，不返回已保存的 UUID。网页订阅使用“饼干 › 用途 › 网页同步对象”固定绑定的饼干，与浏览及默认发言身份独立。
- 导航“订阅的串”在当前标签打开列表，可切换 App／网页来源、分栏阅读或关闭分栏后进入整页阅读。设置与列表标明来源、对象及配置代次。更换 UUID／网页绑定递增代次，只切换集合，保留旧远端集合与本地阅读资料；切换查看来源不修改代次或发言身份。
- 列表逐页读取，明确显示取得时间、已读页范围和后续未读范围；短页不算末页，缺失回复统计保持未知。有效空页仅是结束候选，不保证同一时刻的完整集合。认证错误、结构变化或缺页不当作空集合；已有观察保留并标明时效。后台读取与回读共用一个通道，前台阅读优先；一次读取／连续核对任务有 20 秒时限，可停止排队和后续读取，不自动重试。
- 可以按串号加入、加入当前阅读的串，或取消某个列表项。确认时显示固定对象，主进程先持久保存意图再请求。虽然论坛增删接口使用 GET，它们仍是显式写入，不由列表刷新、预取或重启触发。
- “服务端报告成功”和“回读看到存在／缺项”分别显示。重复调用可能仍报告成功，不表示每次改变了一项。取消的缺项结论必须有原有效观察、成功报告和从首页连续读至结束候选的回读；查找失败不算取消成功，分页期间外部变化仍可能影响观察。
- 操作记录保留当时的来源、身份引用、代次与前后证据。更换当前来源或绑定不改正在执行或待核对操作的对象。响应丢失、写入后的结果保存中断或核对失败时明确保留不确定性；当前请求结束且存储恢复后，可直接在操作记录中核对，无需重启。“核对”只读取原对象，重启不重放写入，也不补偿删除。旧饼干已移除或系统保护不可用时，原对象不能核对，不会替换身份。
- 写请求遇到限流或验证码时显示对应原因并停止自动回读，保留报告与待核对记录；之后只能由用户明确发起只读核对。
- 远端订阅与本地阅读、收藏及离线数据独立。当前没有提醒规则，不额外询问提醒处理；提醒联动尚未实现。
- 协议参考公开客户端资料及两端最小往返、重复操作的历史观察。当前客户端通过受控 HTTP、真实 SQLite 和 Electron 界面验证；本版本尚未对真实论坛执行身份读取／订阅增删 smoke。多页网页、失效身份、并发和故障恢复的证据为受控场景，不代表线上服务保证。

### 双向同步与 UUID 合并搬运

在“订阅的串 › 同步与合并…”中选择操作；预览只读取，不写入。

- **双向同步**：比较当前 App UUID 与固定网页同步对象，显示各自的本机引用、配置代次、读取页范围与错误。第一次同步或更换对象后，只提出已观察条目的并集新增。确认执行时才建立共同存在的基线，单看预览不建立基线。
- 有确认基线后，曾在两端共同存在、如今一端缺项的串才可能成为删除候选。两端须连续读至有效空页；缺页、认证错误或身份变化时不推断删除，也不自动把基线中的缺项恢复到另一端。缺项仍不证明用户主动删除，结束候选也不是一致快照。
- 读取不完整且没有可安全执行的候选时，预览保留“部分比较”的提示，不把候选为空当作两端一致。删除预览同时说明：这次未读到不证明用户主动删除，连续读取也不是原子快照。
- 新增默认勾选，删除默认不勾选；逐项选择后再次确认。未勾选的删除保持不动。空选择可“记录这次比较”，只保存已观察到的共同事实，不修改远端集合。
- 确认后、第一项写入前，重新读取预览涉及的两端范围。身份代次、集合或页覆盖变化会使整个预览失效，零写入并要求重新预览。这不是服务端锁或 CAS；检查通过后，其他客户端仍可能修改集合。
- 选中的项目按预览列表顺序组成固定计划，确认摘要保持同一顺序；只合并相邻且影响相同的项目，不把新增或删除移到前面。计划串行写入并逐项回读。服务端报告失败／未知或回读无法确认时停止后续写入；保留先前成功，不撤回、不补偿，也不把整批称为原子失败。基线只更新已经确认的事实，逐项结果与对应基线在同一 SQLite 事务中保存。
- “停止后续步骤”可停止排队、读取和尚未开始的项目，不能撤销已发出的写请求。结果不明时只允许明确的只读核对；继续处理须重新预览。
- **合并搬运**：普通更换 UUID 只切集合。另行选择本机曾使用过的旧 App 对象，预览其已观察到、当前集合中未见的条目，再勾选加入当前集合。此操作只新增，保留旧远端集合和本地阅读资料；旧引用仍需要系统凭据保护可用。
- “同步与合并记录”保留固定对象、逐项意图关联、报告与回读结果。重启将未完成计划标为中断，保留已确认项和待核对项，未开始项不执行。预览仅在本次进程有效，没有恢复执行旧计划的入口。

验证使用受控 App JSON／网页 HTML 服务、真实 SQLite 与 Electron 界面，覆盖第二身份、集合／覆盖变化、部分成功、服务端提交后断线、结果保存故障及进程中断后重启。窄窗口与原生 200% 界面缩放已在 Linux WSLg 演练；这些证据不替代 Windows／macOS 原生验收或真实论坛同步验证。


## 阅读行为与限制

- 版面与串阅读使用 JSON 接口 `https://api.nmb.best/api/`（`getForumList`、`getTimelineList`、`showf`、`timeline`、`thread`、`po`），不跟随重定向，不自动重试。选择了浏览饼干时，这些请求带 `Cookie: userhash=…`；未选择时不带任何饼干或凭据。App 订阅使用同站 `/Api/feed`、`/Api/addFeed`、`/Api/delFeed` 的 UUID 参数，不带饼干；网页订阅仅向 `https://www.nmbxd1.com` 的固定列表／增删路径发送固定同步对象的饼干。两者均不跟随重定向。版面与时间线名称中的论坛标记只保留文字。
- 每次读取总时限 20 秒；按实际 `Content-Encoding` 解压，压缩前后体积均有上限。HTTP 200、HTML 页面或可解析的 JSON 本身都不视为成功：论坛返回的“该串不存在”等业务文本、HTML 错误页、结构不符都会显示为对应的失败类别（不存在、权限、限流或验证、网络、结构无法识别）。
- “末尾”按服务端回复数估算一页，再最多向后、向前各探测两页核实；未能核实时显示“覆盖不足”，探测中途失败时显示已探测的页和失败位置，不会跳到估算页冒充末尾，也不会下载全串。
- 目录、串列表或串页中部分条目结构异常时，其余内容照常显示并提示未显示的条目数；全部不可用时按“结构无法识别”处理，不当作空列表，也不覆盖本机已有缓存。
- 论坛插入的 `Tips` 提示项不计为回复；同一页内重复的发言按发言 ID 去重。发言 ID 以十进制字符串保存，不受 JavaScript 数值精度影响。
- 正文由主进程解析为受限结构（文字、换行、强调、引用编号、绿字引用、http/https 链接），界面不插入论坛 HTML，脚本、样式、事件属性和其他标签内容均被移除。链接只能在系统浏览器中打开 http/https 地址。引用编号目前只作展示。
- 帖子时间按论坛原文显示，时区未经核实。

## 数据与安全

- 本机数据保存在 Electron 用户数据目录下的 `xidao.sqlite`，由主进程中的单个数据库 worker 访问（WAL、外键、短事务）。数据库结构单向升级；升级失败时回滚并保留原文件，不删除或重建数据库。用较旧版本打开由较新版本写入的数据库时，以只读方式读取并拒绝写入（此时也不能导入、重命名、移除饼干或修改用途）。
- 阅读模式、阅读位置、已读记录、关注起点、访问记录和设置是个人记录，与缓存的论坛内容分开保存，不依赖缓存内容存在。
- 读取到的图片保存在用户数据目录下的 `images/` 中，文件名由应用生成，数据库记录每个文件是缩略图还是原图、来源地址、取得时间、实际格式与尺寸，缩略图与原图分别记录。同一图片被多条发言或多个标签使用时只保存一份。
- 图片先完整写入临时文件，校验后改名到位，再提交数据库记录；中途失败、取消或写库失败时，已有的文件和记录保持不变，新文件被删除。正在显示图片的阅读视图会保护所用图片不被清理；清理只删除没有任何保护的记录及其文件，不会删除 `images/` 以外的文件，也不跟随符号链接。每次启动时会移除上次中断留下的临时文件和没有记录的文件。界面通过应用自己的 `xidao-image://` 地址读取这些文件，不暴露文件路径。
- 当前版本尚无缓存额度和手动清理入口，已读取的图片会一直保留在 `images/` 中。
- 饼干 userhash 通过 Electron `safeStorage` 的异步接口加密后存入数据库（Windows 为 DPAPI，macOS 为钥匙串）；数据库只保存名称、本地编号与密文。系统保护不可用时（包括 Linux 在没有密钥环服务时的 `basic_text` 后备）拒绝导入，已保存的饼干保持密文、不能用于读取，不会改用明文保存。系统保护防的是数据库文件被直接读取，不能防住以同一登录用户身份运行的其他程序。
- 解密后的 userhash 只在主进程内存中使用：界面只能取得名称、来源、导入时间和用途选择；粘贴内容只在导入时经 IPC 传入主进程一次，导入成功或关闭设置后清空输入框。饼干只附加在主进程发往上述论坛接口的请求上，不写入 Chromium 会话 Cookie，因此界面加载的图片、外部链接等不会携带它。
- App UUID 使用相同的系统密钥保护器，数据库中只有本地引用和密文；更换后保留旧引用对应的密文供固定操作核对及显式合并，常规查询不返回秘密或秘密片段。观察、配置代次、逐项意图／报告、同步基线及计划历史保存在独立表中，不随读取失败清除。
- 界面页面启用 sandbox 与 context isolation，禁用 Node 集成与 webview，使用严格 CSP；不允许页面导航到其他地址或打开新窗口，拒绝所有权限请求。界面只能调用少量具名操作，主进程校验调用页面（仅主窗口主框架中的应用页面）与参数，不提供任意网址、SQL 或文件访问。
- 应用只运行一个实例。

## 开发

需要 Node.js 24 LTS 与 npm（版本见 `.nvmrc`；`.npmrc` 启用了 `engine-strict`）。

```bash
npm ci            # 安装锁定依赖
npm run dev       # 开发模式（热更新）
npm run build     # 构建到 out/
npm start         # 运行构建产物
npm run typecheck # 主进程、preload、共享代码与界面的类型检查
npm test          # Vitest，运行在 Electron 自带的 Node 中，与应用使用同一 SQLite 驱动
```

代码结构：

| 位置 | 职责 |
| --- | --- |
| `src/shared/` | 主进程与界面共享的数据类型、读取结果与具名接口 |
| `src/main/forum/` | 论坛请求（限定来源与可携带饼干的来源、解压、体积与超时）、JSON 规范化与正文安全解析 |
| `src/main/identity/` | 饼干导入解析、系统密钥保护适配、用途选择与浏览身份解析 |
| `src/main/storage/` | 数据库 worker、迁移、覆盖计算、饼干密文与用途选择 |
| `src/main/reading/` | 前台／后台请求通道、读取与缓存回退、末尾有限探测 |
| `src/main/subscriptions/` | App JSON／网页 HTML 适配、UUID 保护、固定对象观察、预览／串行计划与逐项写入／回读恢复 |
| `src/main/images/` | 图片请求（限定来源、无凭据、不跟随重定向）、按文件内容识别格式、受管图片文件与保存 |
| `src/main/ipc.ts`、`src/preload/` | 具名 IPC 与调用方校验 |
| `src/renderer/` | React 界面 |
