# 汐岛

汐岛是 [X 岛匿名版](https://www.nmbxd1.com/) 的第三方桌面客户端，基于 Electron、React、TypeScript 与本地 SQLite，目标平台为 Windows 10 / 11 x64 与 macOS 13+（Intel、Apple Silicon）。

> 项目处于早期开发阶段，已提供浏览阅读、引用与图片、主题和阅读设置、身份与草稿发布、两端订阅和预览同步、历史／离线与缓存、本机／串内和联网搜索、串更新提醒、后台驻留与工作区恢复，以及 Windows 安装程序、macOS DMG 构建配置和应用内软件更新；尚未发布正式版本。

## 当前可用功能

- 左侧圆角图标栏提供“版块”、全部收藏版块的首字入口（顺序同“设置 › 版块管理”）、订阅／提醒／搜索／历史／离线／草稿和底部“设置”；名称首字冲突时显示两字。收藏较多放不下时，收藏区在“版块”与功能项之间单独纵向滚动，有更多内容的一侧边缘淡出，功能项、“更多”与“设置”始终可见；当前版面若是收藏，会滚入可见范围并显示当前态，用 Tab 或方向键移到屏外的收藏时同样滚入。窄窗的浮层图标栏相同。“提醒”上的数字是有新提醒的串数（100 起显示 99+）。功能可在图标栏上直接拖动排序，也可在“设置 › 功能显示”中显示、隐藏并用排序手柄调整顺序；隐藏功能从“更多”进入。“版块”打开可筛选的多列面板，版面显示版规，时间线显示说明。
- 侧栏的收藏版块、订阅、提醒、搜索、历史和离线入口：普通点击仍在当前内容标签打开；Ctrl+点击（macOS 为 Cmd+点击）或中键在当前标签之后新建后台标签，当前页面、输入和焦点不变。“更多”和窄窗导航浮层中的同类入口遵守相同规则，后台打开后浮层保留。新搜索标签从独立的本机搜索开始，历史从“浏览”开始；新标签采用全局分栏默认值。设置仍只打开或激活唯一的设置标签；版块选择器、更多和草稿仍是面板／对话框。
- 串列表按页读取，滚动到底部时追加下一页并按串号去重。
- 串阅读：主帖与回复连续显示，接近底部时按需读取下一页；一行工具栏提供全部／只看 PO、页码跳转、回复、订阅、串内搜索与更多。“更多”的首项是“刷新”，开头／末尾也在“更多”中，也可使用随用户滚动方向出现、静止后隐藏的角落图标或 Ctrl/Cmd+Home／End。追加内容不移动当前视口。
- 每个串可在“全部”与“只看 PO”之间切换；选择按串保存，两种模式各自保存阅读位置。
- 多标签：每个标签有自己的后退／前进历史、当前版面、打开的串和分栏开关。分栏开关是标签栏右侧只有图标的按钮（悬停提示“分栏”，读屏读出按下状态），开启时图标为强调色并加粗，关闭时为灰色。分栏时列表与正文并排，单击列表项只更换正文，不增加后退步骤；关闭分栏时打开串会进入整页阅读并可后退回列表。
- 列表与正文间的分隔条可拖动，或用方向键、Home／End 调宽，双击恢复默认 340px；宽度保存在本机，调整时保留正文的分栏最小宽度。列表行依次显示饼干 ID 与时间、加粗标题、加粗名称、保留换行的摘要（最多约 20 行）与元信息；缩略图为 64px，紧凑密度为 48px。管理员饼干 ID 和 SAGE 使用危险色，选中行首行加粗。各类串列表（版面、时间线、订阅、提醒、离线、历史“浏览”、搜索结果）支持右键“在新标签页打开”“复制串号”（复制主帖串号，格式 `No.123`），以及中键或 Ctrl/Cmd+单击在新标签页打开；联网搜索中尚未定位的回复结果只能复制其链接所在串的串号。显示串主饼干 ID 的串行还有“饼干颜色…”，见“举报、屏蔽与饼干颜色”。历史“新串”“回复”的发送记录行复制记录自己的串号，见“历史、离线与缓存”。
- 置顶串紧凑显示：论坛不提供置顶标记，只是把置顶串排在列表最前，所以汐岛按位置识别。版面或时间线第 1 页的第一条，若主帖由管理员发出，且发帖时间（按论坛服务端时间）比同页第二条早至少 30 天，就视为置顶串。这一行的摘要最多 3 行、末行淡出，缩略图缩小为 48px（紧凑密度 36px），其余内容与点击、右键、选中都和普通行相同，也不加“置顶”标签。同页不足两条、第 2 页及以后、时间无法解析时都不判定，也不为判定额外请求论坛。订阅、提醒、离线、历史和搜索中的同一串照常显示。论坛若改变置顶方式，这条规则可能失效。
- 引用：正文中的引用编号悬停片刻或聚焦后按 Space 显示引用卡片（卡片紧贴引用编号，不再重复编号；关闭按钮在饼干 ID、时间所在的元信息行右端，没有元信息时在提示行右端，始终可用；卡片底部只在需要时出现“打开原串”或“重试”）；鼠标移入卡片或焦点在卡片内时保持打开。单击或 Enter 定位并跳转，定位期间卡片显示“正在定位…”，正文不动。右键引用编号（或聚焦后按 ContextMenu 键／Shift+F10）只弹出引用自己的菜单，不弹出所在发言的菜单：“在新标签页打开”和“复制串号”（`No.123`）；有选中文字时最上方多一项“复制选中文字”。“在新标签页打开”与 Ctrl+单击／Ctrl+Enter（macOS 为 Cmd）相同：定位成功后才新建标签并切换过去，新标签按“新标签默认开启分栏”且不复制原标签历史，原标签的阅读位置保持不变；定位失败时不建标签，在原处的卡片上显示原因。卡片内嵌套的引用编号同样可单击、Enter、Ctrl/Cmd+Enter 跳转或打开新标签，也可右键或按菜单键打开菜单；用 Tab 移到嵌套引用时不自动预览（预览会替换当前卡片），按 Space 或悬停才预览。只按本机已记录的所属串和观察页定位，不扫描全串：所属串未知时只能预览和复制；只知道原串时可“打开原串”，先读取该串续读位置所在的页，读到后才打开并记录历史，打开后持续注明未定位到该回复，读取失败则留在卡片上显示原因和重试；网络失败可手动重试，重试只重新核对、不会自动补做之前的跳转，核对成功后再单击引用编号即可跳转；服务端返回不存在与当前身份无权访问分别说明，显示缓存内容时标明获取时间与失败原因。失败卡片在鼠标移开后仍保留，直到关闭、点击外部、按 Esc 或另选引用。Esc 每次只关闭最上层的浮层。
- 引用跳转与同一标签的后退／前进共用一套历史：跳转成功才记录来源串、列表、阅读位置、模式和触发的引用；当前条目来自引用时，工具栏后退按钮显示“返回引用处”，返回后焦点回到原引用编号。目标已在当前视口内时只短暂高亮，不新增历史。在列表中改选其他串后按钮恢复为普通后退，已有历史保留。
- 引用定位的依据与限制：论坛 `ref` 接口只返回发言内容，不给所属串或页码。定位只用本机读过的串页或列表中记下的所属串，再重新读取最近一次包含该回复的那一页核对编号（先按该串的模式偏好，再试另一模式）；本机没有任何记录时，只核对该编号本身是否为某串主帖。回复移页、只在列表里见过（此时先读取该串第 1 页确认可打开）或从未见过时不会猜测位置。只看 PO 页不含其他人的回复，因此只看 PO 时引用的非 PO 回复，若本机从未在全部回复页或列表中见过它，同样属于所属串未知。目标被只看 PO 隐藏时临时以全部回复显示，不改变该串的模式偏好，也不保存该临时显示的位置；返回时恢复原模式。
- 窄窗口：先收窄正文两侧留白，再把图标栏改为可展开的导航浮层（标签栏中点“打开导航”），空间仍不足时暂用单栏（正文提供“返回串列表”）。正文字号与行距不随窗口改变；窗口变宽后恢复，手动关闭的分栏不会被重新打开。
- 阅读位置按串、按阅读模式保存，见下文“阅读位置”。
- 图片：正文中的附图先显示缩略图，点击后在应用内查看、缩放和保存原图，见下文“图片”。
- 每次读取的内容会保存到本机数据库。网络读取失败时，如本机有该页的已获取内容，会显示该缓存并标明获取时间与失败原因；没有缓存时显示失败原因和重试入口。
- 串的覆盖状态：已取得的页、缺页、结束候选页，以及服务端回复计数与实际取得条数是否一致；只看 PO 的页单独统计，不计入全部回复的覆盖。
- 页码总数按当前阅读模式最新的服务端回复数计算：每页 19 条、向上取整、至少 1 页；只看 PO 使用 PO 回复数。“末尾”直接读取该页，回复数未知时才有限探测。页数不代表已完整取得。无凭据的公开访问已观察到第 100 页以后重复返回第 100 页；汐岛会拒绝重复／倒退页面并提示“论坛只返回到第 100 页”，不把它存成请求的页或结束候选。页码跳转遇到上限时显示最高可读页的开头，“末尾”遇到上限时显示该页的末尾；页码仍显示真实总数（如 `100/116`），并复用已验证的第 100 页响应，不重复请求。用户已观察到带饼干可读取超过第 100 页的真实末页；这不保证所有版面和饼干具有相同访问权限。
- 饼干管理（在“设置”中）：粘贴官网导出内容或原始 userhash 导入饼干，命名、重命名、移除、调整顺序（排在第一的饼干用于浏览），并分别选择默认发言饼干与网页同步对象，见下文“饼干”。
- 发言编辑、草稿与发布：串工具栏“回复”、版面名旁“发新串”打开居中浮动编辑器，内容自动存为本机草稿，可删除并撤销；回复自己的串时可在提示中直接选用哪块饼干；发送记录列出成功的发送；结果不明的发送由汐岛只读核对一次后自动记为成功或转回草稿，不需要用户结束。
- 浏览历史、发送记录、离线副本与普通缓存额度：导航“历史”分为“浏览｜新串｜回复”三页，“离线”打开离线页；设置中查看占用、调整上限和清理，见下文“历史、离线与缓存”。
- 订阅：设置受保护的 App UUID 与固定网页同步对象，切换两端列表、打开串，显式加入／取消一项订阅，或在同步预览中逐串选择“两端都订阅｜两端都取消｜不动”、从旧 UUID 合并；服务端报告与回读事实分别展示，见下文“订阅”。
- 窗口与退出：关闭窗口可后台驻留或退出；编辑内容自动存为草稿，退出前立即保存，只在保存失败时询问；下次启动恢复标签与工作区，见下文“窗口、后台驻留与退出”。
- 提醒：每串独立组合“全串更新”“PO 追更”“引用我的发言”，按论坛回复数的增长计数；导航“提醒”像订阅页一样列出这些串及“全串:3 PO:2 引用:1”式的计数，打开串即清零，见下文“提醒与更新检查”。
- 外观与阅读设置：浅色、深色、跟随系统与自定义主题，正文字体／字号／阅读宽度，舒适／紧凑密度，减少动态效果，界面缩放；见下文“外观与阅读设置”。
- 本机与串内搜索、列表筛选：检索仍保有的文字，按命中发言或主帖字段筛选，定位并逐层返回对应查询现场，见下文“本机搜索与筛选”。
- 搜索页顶部以“本机｜联网”切换，默认本机，各侧保留查询与结果，切换本身不发送请求；联网一侧使用第三方 nmb-search JSON 接口，手动查询／翻页，其失败不影响本机／串内搜索。
- 关于与软件更新：“设置 › 系统 › 关于”显示实际运行版本，检查本仓库 GitHub Releases 的正式版；Windows 可“安装并重启”或在主动退出时自动安装，macOS 下载对应架构的 DMG 后由用户替换，见下文“安装、关于与软件更新”。

## 快捷键

| 操作 | Windows／Linux | macOS |
| --- | --- | --- |
| 新标签／关闭当前标签 | Ctrl+T / Ctrl+W | Cmd+T / Cmd+W |
| 下一个／上一个标签 | Ctrl+Tab / Ctrl+Shift+Tab | Control+Tab / Control+Shift+Tab |
| 刷新当前内容（不重新载入应用） | Ctrl+R | Cmd+R |
| 保存当前编辑为草稿 | Ctrl+S | Cmd+S |
| 当前串内搜索／本机内容搜索 | Ctrl+F / Ctrl+Shift+F | Cmd+F / Cmd+Shift+F |
| 当前标签后退／前进（引用来源显示“返回引用处”，搜索来源显示“返回搜索结果”） | Alt+← / Alt+→ | Cmd+[ / Cmd+] |
| 引用编号聚焦时：定位跳转／预览／在新标签页打开并切换／引用菜单 | Enter / Space / Ctrl+Enter / ContextMenu 键或 Shift+F10 | Enter / Space / Cmd+Enter / Shift+F10 |
| 发送焦点所在编辑 | Ctrl+Enter | Cmd+Enter |
| 打开设置 | Ctrl+, | Cmd+, |
| 界面放大／缩小／还原 | Ctrl+= 或 Ctrl++（含小键盘）/ Ctrl+- / Ctrl+0 | Cmd+= / Cmd+- / Cmd+0 |

后退／前进在输入框内不生效，不使用 Backspace 后退。打开设置与界面缩放在输入框内也可用。Esc 通常只取消正在进行的定位／联网查询或关闭最上层可关闭浮层，并归还焦点，不会后退；已知本机搜索输入框中第一次按 Esc 会清空输入。Ctrl/Cmd+Shift+F 打开默认本机一侧的统一搜索页，可再切到联网；串中 Ctrl/Cmd+F 打开“串内搜索”。新标签默认分栏只影响之后新建的标签。

页面次要按钮在不可用时仍保留原有键盘导航位置，并向辅助技术报告不可用状态；忙碌不会把焦点移走。点击、Enter、Space 和输入框回车都经过同一业务条件检查，不会绕过不可用状态或重复发起请求。此规则不把输入框、主按钮、分段控件和所有对话框按钮一并改成可聚焦。

页面内的成功操作结果（如订阅完成、删除离线副本、删除历史、缓存清理和索引重建）在离开该页面、切换标签或关闭所在弹窗／设置页后清除，回来不再显示；分栏中仍可见的页面不受影响，窗口最小化或收进托盘也不会清除。失败、结果未知和需“核对订阅”的提示保留原有处理方式；编辑器的“已发送”提示不在此规则内。

右键（或聚焦后按 ContextMenu 键／Shift+F10）输入框和文本域，菜单为“剪切”“复制”“粘贴”“全选”，当前不可用的项置灰：没有选中文字时不能剪切和复制，只读时不能剪切和粘贴，空框不能全选，停用的框全部置灰。饼干导入框和 App 订阅 UUID 框遮蔽时只能粘贴，点“显示”后才能剪切、复制和全选。在没有自己菜单的区域选中文字后右键，菜单只有“复制”；在发言、串行或引用编号上选中文字后右键，仍打开该处原来的菜单，最上方多一项“复制选中文字”（选区不在这条发言、这一行或引用所在正文内时不显示）。既没有输入框也没有选中文字的地方右键不弹出菜单。Ctrl/Cmd+X／C／V／A 仍由系统编辑菜单处理。

## 发言编辑与草稿

- 串工具栏“回复”、版面名旁“发新串”打开居中模态浮动编辑器，没有底部常驻栏或抽屉；时间线没有发新串入口。页头显示可点击更改的目标、饼干列表和“收起”。回复优先使用该串记住的饼干，否则使用默认发言饼干；更换默认饼干不会改变已有编辑。
- 该目标已有编辑时恢复它，否则新建，不会自动套用草稿库中的旧稿。同一个串（或同一版面的发新串）只有一份编辑，在任何标签打开都是同一份内容；不同目标各自独立。正文无框并随内容增长；标题、名称按需展开，没有 E-mail 字段。可附一张图片（添加／更换／移除，有图时可开关水印）并选择饼干；饼干列表按用户顺序显示当前选择和用途标签，支持方向键、Enter、Esc，关闭后焦点回到入口，末尾“管理饼干”直达设置。改目标不换饼干，本标签随即打开新目标；新目标已有编辑时不改。
- 在回复编辑中选择饼干会同时记住为该串的选择；新串编辑中的选择只影响这份编辑；从草稿继续不会改写串的选择。饼干被移除后显示“已移除，需要重新选择”，不会改用默认饼干。
- 同一标签切到别的串或版面时，原编辑收起保留（文字、图片、目标、饼干），回来即恢复。Ctrl/Cmd+R 刷新与 Esc 都不会清空编辑。
- 打开设置标签会隐藏浮动编辑器而不丢内容，切回原阅读标签后恢复展开状态。
- 编辑内容自动存为草稿：正文、标题、名称任一不是空白或有附图时，停止输入约 1 秒后保存（含附图）；第一次保存创建草稿，之后更新同一份。收起编辑器、关闭标签、窗口隐藏（后台驻留、最小化）和退出前立即保存尚未落盘的修改。空白编辑不建草稿；已有草稿的编辑被清空后删除这份草稿。Ctrl/Cmd+S 立即保存焦点所在的编辑（焦点不在编辑中时为当前标签可见且展开的编辑，正文优先于列表）；原图浮层打开时 Ctrl/Cmd+S 仍是保存原图。
- 工具栏左侧状态只显示“已存草稿 时间”（时间格式同其他本机记录）；保存进行中保留上次的时间位置，空白或尚未保存时不显示。保存失败时显示“草稿没能保存”及原因，编辑内容不变，下次修改或收起时再试。没有“保存草稿”“放弃修改”按钮；有草稿时右侧为危险色文字按钮“删除草稿”和“发送”。“删除草稿”删除这份草稿并清空、收起编辑，底部通知“草稿已删除”附“撤销”：撤销把内容（含附图）重新存为草稿，放回草稿列表；该编辑仍开着（所在标签未关闭）时内容同时回到这个编辑，展开或收起状态不变，不打开新的编辑、弹窗或标签。该编辑此后已写入新内容或正在发送时不放进去，改为通知“草稿已恢复”并说明原因，可从“查看草稿”打开草稿库。通知关闭后不能再撤销，附图副本随之回收；撤销不跨重启。
- 草稿删除通知使用轻量文字“撤销”与关闭图标。累计显示 10 秒后自动关闭并结束撤销；鼠标停留、键盘焦点在通知内、窗口失焦或隐藏、通知被附图预览或退出等待等模态层遮挡而不可操作，以及正在撤销时暂停计时，恢复后继续剩余时间。撤销失败的通知保留，可重试或手动关闭。发送失败、限流和软件更新等需要处理的通知不套用这个自动关闭期限。
- 关闭标签（按钮或 Ctrl/Cmd+W）时先保存只在这个标签中打开的编辑（包括切串后收起的），保存仍在进行时等它完成并按最新内容再存一次，全部保存成功就直接关闭；仍在其他标签打开的编辑保留。只有保存失败时才询问“草稿没能保存”，列出失败项与原因，可“仍关闭”（这些修改丢失）或“取消”。浮动编辑器展开时它是模态层，Ctrl/Cmd+W 等标签快捷键不作用于背后的标签，需先收起。
- 导航中的“草稿”列出全部草稿（同一目标可有多份），显示目标、饼干、摘要、是否有图与保存时间。“继续”：该稿已在某个标签编辑时切到那个标签；同一目标已有另一份编辑时，先保存那份编辑，再把所选草稿载入同一编辑器（原内容留作另一份草稿）；否则在新标签打开原目标。草稿库和编辑器的删除均一次生效，不再二次确认；删除正在编辑的草稿只关闭对应编辑，其他草稿和编辑保留。草稿库删除后焦点移到相邻项，空库时回到关闭按钮；底部通知浮在草稿库之上，可直接“撤销”，草稿（含附图）回到列表，不打开编辑。草稿库可用 Esc、关闭按钮或在窗口外的遮罩上按下并松开关闭。发送中、结果待确认或发送记录读取失败而无法确认锁态时不能删除；删除失败保留草稿并说明原因。附图保存为本机副本，不会改动所选的原始文件；重启后可从草稿恢复文字、饼干与图片。
- 附图以 34px 小片显示，点击打开与正文图片共用的缩放、拖动预览；“颜文字”打开预设面板，点击插入到正文光标处（替换选中文字）。面板末尾可添加自定义颜文字，保存在本机，悬停或聚焦后可删除（Delete 键同样删除），不能编辑，需删除后重新添加：
  - 内容为多行文本框，Enter 换行，Ctrl/Cmd+Enter 或“保存”保存，Esc 取消添加；粘贴的 CRLF／CR 换行统一为 LF。内容不能为空白或含换行、制表符以外的控制字符，每条最多 500 字，最多 200 条，不能与预设或已添加的内容重复。
  - 可选“名称”：去掉首尾空白后 1–16 字、单行，可与其他名称重复。有名称的项像“大嘘”等预设一样以界面字体显示名称，悬停显示完整内容；点击总是插入完整内容。
  - 面板顶部的“最近使用”一行列出最近插入的颜文字（预设与自定义都算），最多 8 个，最近的在前，同一内容只出现一次；从这一行插入同样会移到最前。这一行在打开面板时排好，插入时不会在指针下移动，下次打开才按新顺序显示。有名称的项照常显示名称；删除自定义颜文字会把它一并移出；还没有插入过时不显示这一行。
- 颜文字也作为装饰出现在几处：各列表和页面的空状态（标题上方或同一行末尾）、串不存在／已删除的读取失败、页面内的读取失败和出错提示、警示类底部通知的标题末尾，以及“关于”里的汐岛名称旁。每种状态固定用一个，都取自上述预设列表；装饰对读屏隐藏，不能聚焦、点击或随文字选中，不出现在表单校验、按钮、输入占位、系统通知和提示气泡中。

## 发布与确认

- 点击发送按钮，或在编辑器内按 Ctrl/Cmd+Enter。Enter 只换行；输入法组词、按键重复和编辑器外的同一快捷键不会发送。发送先检查目标、所选饼干、附图和目录中已知的版面间隔；同一实际饼干只允许一个发送流程，过程中移除并重新导入该饼干也不能并发发送，其他编辑不会排队自动发送。
- 发送前在本机持久化固定的目标、饼干引用、全部文字与附图引用。等待期间不能修改这些内容；切换标签或全局默认饼干不改变请求。
- **已发送且编号确认**：结束编辑，保存确认记录，删除对应草稿，回收不再被引用的附图。**明确失败**：内容写回编辑器正在继续的那份草稿（编辑还没有草稿时新建一份并绑定），草稿库中不会出现第二份；显示原因；只有用户再次发送才重试。结果不明经核对转为失败时同样写回这份草稿。失败已记录但暂时读不到这份草稿时，编辑器保持锁定并提示正在重新读取，读到后再继续它，不会另建一份。限流、验证码同样停止，不自动重试。发送请求在连接（含 TLS 握手）建立之前就失败时（无法解析域名、连接被拒、网络不可达、建立连接超时），论坛不可能收到请求，按明确失败处理；附图在发送前无法读取也一样。
- **明确失败的通知**（请求已经发出、论坛的判定确定未生效：拒绝、限流、验证码、论坛判定饼干无效等；以及上述连接建立前就失败的发送；内容已自动存为草稿，编辑器保持打开并绑定该草稿）：汐岛窗口可见且获得焦点时，在内容区底部显示“发送失败：<原因>，内容已存为草稿”，附“打开草稿”“知道了”；但发送失败的那个编辑器此时仍展开在当前标签中时不显示（编辑器内已有失败原因并已绑定草稿），之后收起编辑器也不补发。编辑器已收起或已切到别的标签时照常显示。窗口未获焦点、最小化或隐藏在托盘时改发系统通知，标题是失败原因，正文是目标（如“回复 No.123”），不含正文、饼干或凭据，点击后显示窗口并打开该草稿；系统通知不可用或显示失败时，下次显示窗口补一条底部通知。“打开草稿”：该草稿已在某个编辑器中时切到那个标签并聚焦，否则与草稿库的“继续”相同，打不开时在通知里说明原因。发送前即被拦下的情况（饼干或附图不可用、空正文、目标无效、饼干忙、发言间隔等，请求没有发出，也不存草稿）按本地校验处理，只在编辑器里说明，不发通知；串号未确认按成功处理，结果不明的发送经核对未找到而转为失败时只在编辑器和启动提示中说明，也不发失败通知。退出收尾期间无人在场时的失败仍只用退出通知和下次启动提示。
- **论坛提示**：明确失败时，若论坛返回页面中有 `<p class="error">` 元素，汐岛把该元素自身的文字（不是整页）合并空白后作为论坛原话保存在这次发送记录中，最多 120 字，超出时截断并以“…”结尾（省略号计入 120 字）。编辑器的失败提示在原因下方显示完整的“论坛提示：<原文>”；底部通知在原因下方加一行，最多显示 2 行、超出省略，悬停可看全文，读屏读出全文。系统通知仍只有分类后的原因，不含论坛原文。原文一律按纯文本显示，不解析 HTML；没有该元素或元素没有文字时不显示这一行。此前记录的失败没有论坛提示。
- 底部通知可多条同时显示（例如与提醒限流提示并存），按出现顺序自上而下堆叠，各自关闭；窗口隐藏时到达的通知等窗口再次显示才出现，顺序不变。限流提示等与编辑器无关的底部通知不受上述编辑器规则影响。任何弹窗（草稿、离线副本、确认框、发言编辑器等）打开时，底部通知显示在弹窗与遮罩之上，可直接点击，也排在弹窗的 Tab 循环里（弹窗自身的控件之后）；“撤销”“知道了”“稍后”“立即安装并重启”等就地生效，不关闭弹窗；“查看更新”“打开草稿”“查看草稿”等先按弹窗自己的关闭方式（等同 Esc、确认框即取消）关闭弹窗再前往，弹窗忙碌不能关闭时不执行。通知消失时焦点留在最上层弹窗内。例外是退出时保存工作区的等待框：它打开期间整个窗口（包括底部通知）不可操作。系统通知的显示与点击只在 Linux 受控环境中以替身验证，Windows／macOS 原生显示尚未验证。
- **已发送，串号未确认**：论坛报告成功，但没能确认这条发言的编号。按成功发送处理（结束编辑、删除对应草稿），记入发送记录但没有串号；约 10 秒后只读核对一次，找到这条发言就补上串号，找不到则保持没有串号。核对补上串号（或把结果不明的发送判为成功或失败）后，已打开的历史“新串／回复”页和草稿库随即重新读取本机记录，无需手动刷新；核对没有改变记录时不重新读取，也不反复查询。
- **发送结果不明**：连接建立之后中断、超过发送时限，或上次退出时仍在发送。论坛可能已经收到，汐岛不自动重发；编辑器保持锁定并显示“正在确认是否已发出”，约 10 秒后（上次遗留的在启动后）只读核对一次：找到即为发送成功；否则转为失败，内容（含附图）存为草稿，并提示“可能已经发出，重发前先到串里看一眼”。
  - **核对规则**：用发送时的饼干只读目标串末尾（至多 3 页，读到早于发送的页即停）或目标版面前 2 页，寻找饼干 ID、正文（与回读确认相同的比较）、填写的标题和名称、有无附图都与这次发送一致、论坛时间不早于发送前 2 分钟、且串号未被其他发送记录占用的发言；恰好一条才算找到。找到多条、读取失败或被限流、发送时没有记下饼干 ID、饼干已不可用，都按没找到处理。核对逐个进行，不调用发帖接口。
  - 限制：论坛显示新发言有延迟或发言已翻出读取范围时会漏找，此时已发出的内容也会转为草稿；重发前请先确认，否则会重复发帖。
- **发送后自动更新**：只看发送当时的结果，只作用于发出这次发送的标签。
  - 回复确认编号后，如果该标签仍显示这个串，先刷新串，再在原阅读器中滚动到自己的回复并高亮，保留已加载的其他页，不重新显示骨架占位。这仍是该标签新的后退步骤，后退控件显示“返回引用处”，后退回到点击发送时的阅读位置（等待结果期间继续阅读也一样）。回复不在已读取的范围内时，先读取串尾（全部模式）再定位；只看 PO 时按引用规则临时显示全部回复。无法定位时只保留刷新。
  - 新串（包括在值班室发出的举报）确认编号后，如果该标签仍显示目标版面，先重新读取版面列表第 1 页（取代正在进行的列表刷新），再在该标签打开新串，作为新的后退步骤：分栏时新串显示在列表旁，旁边的列表已列出新串；整页时进入整页阅读；后退都回到已列出新串的版面列表。列表读取失败时照常打开新串，列表显示刷新失败。
  - 编号未确认时不跳转：回复只刷新该串，新串只重新读取版面列表。
  - 该标签已离开该串或版面时什么也不做。别人的新回复仍不移动视口。
- 发送记录只列成功的发送（含串号未确认的），保存当时固定的内容、实际使用的饼干和确认到的编号；明确失败的内容只在草稿中。没有按作者收集的“我的发言”库，也没有为旧发送补编号的入口。回读确认自己的主帖时初始化串内饼干选择，但不覆盖已有明确选择。
- 回复时，若本机已存的主帖饼干 ID 与已导入饼干的饼干 ID 相同、而当前编辑选择的是另一块饼干，先询问“用哪块饼干发送？”：单选列表第一项为当前饼干，其后是饼干 ID 与主帖相同的全部已导入饼干（按饼干列表顺序），每项显示名称与饼干 ID；无法解密的饼干列出但不能选，并写明原因。默认选中第一块可用的 PO 饼干，没有时选中当前饼干。方向键切换，Enter 或“发送”用所选饼干发送，Esc 或“取消”不发送、不改变身份。选 PO 饼干时与发送意图一起保存为该串的发言饼干，编辑也改用它；选当前饼干不改变串内选择。主进程只接受这次提示列出的可用饼干。主帖未存在本机、主帖没有饼干 ID 或没有饼干与之匹配时不提示；饼干 ID 未知的饼干不参与匹配。“本次启动不再提示”只在确认发送后生效，跨串保留直到进程真正退出；设置中的长期提示开关会持久保存，重新开启立即清除临时抑制。这一匹配只是提示，不作为发送成功或编号归属的证据。
- 发布仅使用主站 `https://www.nmbxd1.com/Home/Forum/doPostThread.html` 或 `doReplyThread.html`，与浏览饼干和订阅来源无关。单图 multipart：新串 `fid`、回复 `resto`，文字字段 `content/title/name`（不提交 `email`），附图 `image`；水印关闭省略 `water`，开启传字符串 `true`。POST 总时限 60 秒，不跟随重定向。省略 `email` 的请求已在 Windows 试用构建上由用户确认真实回复与新串发布成功；不代表所有版面、身份或服务故障分支均已线上验证。
- 成功标记不等于编号确认：立即用同一临时会话请求一次 `/Api/getLastPost`，核对目标、正文与编号，再通过不带饼干的公开串页或 `/api/ref` 回读。论坛把骰子 `[n]`／`[n,m]` 存为“加粗的结果＋小字原式”（如 `[1,5]` 存为 `<b>2</b><small>[1,5]</small>`），核对时把这一对还原为原式再比较，其余正文仍须完全一致；阅读区照常显示论坛渲染的结果。读取总时限 20 秒；空值、不符、已被其他发送记录确认的编号和不可确认的竞争结果均记为串号未确认，不循环查询（之后只有上文的一次核对）。论坛没有提供客户端幂等键；本机锁只能防止汐岛重复提交，无法排除其他客户端同时使用同一饼干造成的所有歧义。

## 举报、屏蔽与饼干颜色

- 在阅读器中右键发言（或聚焦后按 ContextMenu 键／Shift+F10）可选“回复”“举报”“屏蔽串号”“屏蔽饼干”“复制内容”“复制串号”“复制饼干”“饼干颜色…”。发言旁的饼干 ID 与某块已导入饼干的饼干 ID 相同时视为自己的发言：同样可以回复和举报，不显示两个屏蔽项。饼干 ID 在设置中补填或修改后立即生效。串工具栏“更多”里也有“举报”（举报主帖，自己的主帖同样可用）和“在新标签页打开”。
- “复制内容”复制本机保存的正文纯文字：保留换行，正文里的 `>>No.` 引用文字和防剧透标记 `[h]…[/h]` 保持原样；不带标题、名称、饼干 ID、时间、本条串号和图片。没有正文的发言该项置灰。“复制串号”复制 `No.` 加这条发言的串号；“复制饼干”复制发言公开的饼干 ID，没有饼干 ID 的发言不显示该项。
- 举报沿用论坛值班室（版面 18）的版规格式：在值班室发新串，正文为 `举报理由：<理由>`、`>>No.<编号>` 和补充内容。理由可选 黄赌毒、政治敏感、谣言欺诈、广告q群、引战辱骂、串版、错字自删、错饼自删，或“其他”并自行填写。举报走普通发言流程：选择饼干、先在本机记录、出现在发送记录中，只有按“发送”才会发出。
- 屏蔽只保存在本机：被屏蔽的回复在串内折叠为一行“已屏蔽 No.…”，可点“显示”临时展开；屏蔽的主帖编号或楼主饼干会让该串从版面与时间线列表中隐藏，订阅、历史与搜索结果不受影响。“设置 › 屏蔽”列出全部屏蔽项并可取消。
- 饼干颜色只保存在本机，只改变饼干 ID 文字的颜色，不加备注，也不影响屏蔽、PO 标记或论坛内容。“设置 › 饼干颜色”（在“屏蔽”之后）按添加时间列出已标色的饼干 ID（以其颜色显示），可筛选、改色、删除，也可手动输入饼干 ID 添加；该 ID 已有颜色时改为更新颜色。饼干 ID 按原文精确匹配（区分大小写），填写规则与饼干 ID 相同（去首尾空白后 1–32 个字符，不含空白和控制字符）。
- 右键入口：发言菜单在“复制饼干”之后有“饼干颜色…”（自己的发言同样有）；版面、时间线、订阅、提醒、离线、历史“浏览”和“新串”的串行菜单在“复制串号”之后有“饼干颜色…”，作用于串主的饼干 ID。本行不知道串主饼干 ID 时（没有本机主帖、搜索结果、历史“回复”行——它显示的是发送时用的饼干）不显示该项，也不为补全而联网；管理员的发言和串行同样没有。选择后在该饼干 ID 旁（它不在视野内时在菜单处）弹出色板：8 个色块和“清除颜色”，顶部显示当前颜色，当前色块带勾。方向键移动、Enter 或 Space 选择，选择即保存并在所有位置立即生效；Esc 关闭，焦点回到原来的发言或串行。“清除颜色”删除该 ID 的颜色，恢复普通文字颜色；自己饼干的默认颜色被清除后不会再补回。
- 颜色来自 8 种具名颜色的固定色板，不含红色系；浅色、深色主题各有取值，在饼干 ID 出现的各种底色（含选中行）上对比度不低于 4.5:1，自定义主题按所在一组的正文文字颜色调整。发言、引用卡片、版面／时间线／订阅／提醒／离线串行、历史“浏览”与发送记录行、“设置 › 饼干”中的饼干 ID 都按颜色显示，修改后立即生效；管理员的饼干 ID 始终为红色。搜索结果仍不显示饼干 ID。
- 自己的饼干：导入饼干、重新导入时补上饼干 ID、在设置中填写或修改饼干 ID 时，该饼干 ID 自动得到默认颜色（蓝），所有导入的饼干共用这一颜色；该 ID 已有颜色时不覆盖。每个饼干 ID 只自动分配一次，之后改色或清除都不会被补回；删除饼干不删除其颜色。

## 窗口、后台驻留与退出

- 点击窗口关闭按钮时，“关闭窗口时”为“每次询问”（默认）会询问“后台驻留”或“退出汐岛”；勾选“记住我的选择”后不再询问，可在“设置 › 窗口”中改回。Esc 或对话框的关闭按钮只取消这次关闭。
- 后台驻留只隐藏窗口，标签、阅读位置和编辑都原样保留；窗口隐藏时尚未保存的编辑立即存为草稿。Windows／Linux 从系统托盘图标重新打开（单击或菜单“打开汐岛”），托盘菜单的“退出汐岛”走正常退出；macOS 从 Dock 图标重新打开。再次启动汐岛也只会唤起已运行的窗口，不会启动第二个进程。窗口获得焦点不算重新打开。
- 真正退出（关闭时选择退出、应用菜单或 Cmd+Q、托盘“退出汐岛”）按顺序进行；从开始到退出完成或取消，窗口只响应退出流程自己的对话框，不能再修改编辑或标签：
  1. 关闭打开中的对话框，取消待回答的 PO 饼干提示；对结果未确认的发送再检查一次，仍无法确认时不退出。
  2. 立即把所有标签中尚未保存的编辑（包括切换页面后收起的）存为草稿，不再询问。只有保存失败时才显示“草稿没能保存”，列出失败项和原因，可“仍退出”（这些修改丢失）或“取消退出”。
  3. 保存工作区：标签及其顺序、当前标签、各标签的后退／前进历史、分栏开关与所在页面、阅读位置、列表已读取的页数（最多 10 页）与滚动位置，以及哪些标签打开着哪份草稿（收起或展开）。保存失败时停在“工作区未能保存，未退出”，可重试或取消退出。
  4. 关闭窗口并停止后台读取、搜索获取和索引任务，保留已完成内容；退出期间重开只建立新的搜索会话，必要时重建中断索引，不重放旧获取。已经开始的发送只等到原本的 60 秒时限，不重新计时或重发；到时限仍无结果记为结果不明（下次启动时核对），论坛已接受但未回读确认记为串号未确认。
  5. 发送结果写入本地存储后才结束进程。结果写不进存储时不退出：窗口重新打开并显示“发送结果未能保存，未退出”，“重试”只保存结果、不发送任何内容，保存成功后继续退出；“取消退出”继续使用。
- 退出等待期间再次打开汐岛会取消这次退出并恢复刚保存的工作区；之后到达的发送结果只更新发送记录。
- 无人在场时失败或结果不明的发送，会尝试发出一条系统通知；下次启动时在内容区底部为每个这样的发送显示一条通知，写明目标与结果（“发送失败，内容已存为草稿”“可能已经发出，内容已存为草稿”或“正在确认是否已发出…”），有草稿时附“打开草稿”（与发送失败通知相同：已在编辑中就切过去，否则像草稿库“继续”那样打开），以及“知道了”。结果不明的发送在启动后核对，对应通知原地更新：找到的移出，没找到的改为可能已经发出、内容已存为草稿。超过 3 条时只显示前 3 条，另有一条“还有 N 个发送没有完成”可打开草稿库。这些通知与限流、发送失败通知一起堆叠、各自关闭，“打开草稿”或“知道了”后不再显示。系统通知不可用不影响退出，也不会丢失启动通知。上次异常结束时仍在发送中的尝试，启动时同样按结果不明处理。窗口顶部的通栏只用于数据库只读或存储不可用。
- 启动时恢复工作区，不发送任何内容；列表从第 1 页起重新读取保存时的页数后回到原位置。已不存在的串在原位置显示对应错误，已不在目录中的版面或时间线显示“已不在目录中”，都不自动跳走。正在发送或结果不明的草稿不会重新打开为可编辑的编辑。工作区记录损坏或不兼容时以全新工作区启动。
- 验证范围：Linux 受控环境已验证退出收尾与通知调用；Windows 11 x64 与 Apple Silicon Mac 原生已验证隐藏窗口后再次启动只唤起原窗口、草稿保留及正常退出。Windows 托盘单击与菜单打开／退出、macOS Dock 点击重开均已验证；两平台系统通知的实际显示与点击仍待原生验收。托盘使用应用图标（Windows 为多尺寸 ICO），随安装包打包。
- 系统关机、重启或注销时（Windows），汐岛立即保存尚未落盘的草稿与工作区，不询问、不阻止关机；系统可能在保存完成前结束进程。

## 安装、关于与软件更新

- 安装包：Windows x64 为 NSIS 安装向导 `xidao-<版本>-win-x64.exe`；macOS 分别为 Intel 与 Apple Silicon 的 `xidao-<版本>-mac-x64.dmg`、`xidao-<版本>-mac-arm64.dmg`，要求 macOS 13 及以上。下载文件名用 `xidao`：GitHub 发布会改写非 ASCII 文件名，而更新元数据按原名引用安装包。Mac 包内应用为 `汐岛.app`，Finder、Dock 与应用显示名统一为“汐岛”；Windows 可执行文件仍为 `xidao.exe`，快捷方式显示“汐岛”。
- Windows 安装向导（简体中文）依次选择：安装方式“仅为我”（默认，装到用户目录，不需要管理员权限）或“为所有用户”（需要管理员授权）；安装位置（所选目录不以应用名结尾时自动补 `xidao` 子目录）；是否“创建桌面快捷方式”（默认勾选）；完成页可直接运行汐岛。开始菜单快捷方式始终创建。已经安装过时，安装方式页预选原来的方式，另一种不能选并注明需先卸载，因此不会在另一种方式下装出第二份。卸载删除程序与快捷方式，保留数据目录。
- 应用身份固定为 `io.github.qiyi71w.xidao`、产品名“汐岛”，数据仍在原 Electron 用户数据目录（Windows `%APPDATA%\汐岛`，macOS `~/Library/Application Support/汐岛`）；升级和卸载都不删除数据。
- 签名：Windows 安装程序与应用没有开发者签名，首次运行可能出现 SmartScreen 提示；macOS 只有临时（ad-hoc）签名，没有 Developer ID 与公证，首次打开需按系统提示放行，换用新版本后钥匙串可能再次请求授权（拒绝时已加密的数据保留不变，需恢复授权后才能读取）。安装包校验只证明下载内容与发布元数据一致，不等于开发者认证。
- 图标：应用、安装程序、托盘与“关于”使用同一套汐岛图标（`resources/icons/`）。
- 解压即用的试用副本不是安装版：“关于”显示“当前不是安装版，不能在应用内更新”。

### 关于

“设置 › 系统 › 关于”显示图标、名称、实际运行的版本（只此一处）、仓库 `https://github.com/qiyi71w/xdnmb` 与作者 `https://github.com/qiyi71w`，全部更新操作和设置也集中在这里。

### 检查与下载

- 更新源在构建时固定为本仓库 GitHub Releases 的正式版（不含预发布），界面不提供其他来源。请求只发往 `github.com` 上本仓库的发布路径和 GitHub 的发布文件服务器，每次跳转都重新核对；版本号、本机系统与架构对应的安装包文件名和 SHA-512 格式不符时拒绝。更新请求使用独立的内存网络会话，不带论坛饼干、任何 GitHub 令牌或其他凭据。
- “自动检查更新”默认开启：冷启动后检查一次，之后运行期间（包括后台驻留）每 24 小时检查一次；聚焦或重新打开窗口不会检查，与论坛提醒的定时和冷却无关，检查不会并发进行。关闭后仍可随时手动“检查更新”；检查进行中按钮保持焦点但不能再次触发。检查失败显示原因，不会显示为“已是最新版本”。
- 发现新版时显示版本号、发布时间和该版本在 GitHub 上的更新说明：只呈现标题、段落、列表、代码和 `https` 链接，不执行其中的 HTML 或脚本；长说明可展开，可“在 GitHub 查看”；发布没有说明时显示“此版本未提供更新说明”，取不到这一版本自己的说明时显示“未能取得此版本的更新说明”，不会显示其他版本的说明。同一版本只弹出一次底部通知，设置图标保留小圆点，设置按钮的名称同时包含“有新版本”，此时点击设置按钮直接打开“关于”。
- 下载显示实际进度，可取消；取消后本次运行不会再自动下载这一版本。下载内容必须与发布元数据中的 SHA-512 一致，否则删除并提示；校验完成前不能安装或打开。已下载的安装包和说明保存在本机，重启后无需联网仍显示“已就绪”；该版本成为正在运行的版本，或有更新的版本取代它时，旧安装包被删除。
- 安装包就绪后另显示一次底部通知：Windows 可选择“立即安装并重启”或“稍后”，macOS 可选择“打开安装包”或“稍后”。通知不弹模态窗口、不抢编辑焦点；“稍后”只关闭通知（Windows 开启自动安装时注明“退出汐岛时安装”），本次运行同一版本不再提示，仍可在关于页操作。下次启动仍有待装包时会再次提示。
- 更新网络：“系统代理”（默认，按操作系统的代理设置，Windows 即系统代理设置而非环境变量）或“直连”，只用于检查更新和下载安装包。论坛、图片、联网搜索与官网登录使用另一套网络连接，不受这一设置影响。

### Windows 安装

- “安装并重启”：先核对安装包，再走正常退出流程（保存草稿与工作区、等已开始的发送在原时限内收尾），关闭数据库后静默安装，安装完成后重新打开汐岛。
- “退出时自动安装更新”默认关闭。开启后发现新版会自动下载，并在用户主动退出汐岛（关闭窗口时选择退出、托盘或应用菜单）且上述收尾成功后安装，安装后不自动重新打开。关闭此项时普通退出不安装。退出时若安装包尚未下载完成，不会临时下载，也不安装。
- 取消退出、草稿或工作区保存失败、收尾期间重新打开窗口，都会取消这一次安装并保留安装包。后台驻留不安装；系统关机、重启或注销期间也不启动安装器。
- 自动安装开启、包已就绪时，Windows 会话结束会保存一次待装记录。下次启动在取得单实例锁后、打开数据库与主窗口前消费记录，重新核对版本和 SHA-512，再显示原生安装进度，完成后打开新版；不需要先打开设置库。校验失败删除包；安装器无法启动，或安装器结束时汐岛仍是原版本（例如拒绝了管理员授权），保留包、正常进入原版本并在关于页说明原因，本次待装记录不再自动重试。自动安装关闭时，关机后照常进入应用并保留就绪包。
- 应用内安装沿用已有安装的方式、位置与快捷方式，不显示向导的任何选择页，也不会重新创建被删掉的桌面快捷方式。“仅为我”安装静默完成；“为所有用户”安装每次都会出现 Windows 管理员授权提示，拒绝即不安装。退出时启动的安装没有让汐岛换成新版本时，下次启动在关于页说明“上次退出时未能安装新版本”，安装包保留。
- 安装使用 electron-updater 的 NSIS 升级参数 `--updated`；主动退出时加 `/S` 静默安装，启动安装保留原生进度窗口（结束后不停在完成页），需要重开时加 `--force-run`。安装时机由汐岛的生命周期控制，不使用更新库“退出即安装”的默认行为。

### macOS

“自动下载更新”默认关闭；开启后发现新版即下载对应架构的 DMG，否则由用户点击“下载更新”。校验完成后提供“打开安装包”：请先退出汐岛，再把新版拖到“应用程序”覆盖旧版。汐岛不会自行替换或强制退出，打开安装包不算升级成功，下次启动显示实际运行的版本。

早期试用包的应用文件名为 `xidao.app`。换成 `汐岛.app` 时，请先正常退出旧版，将新版放到“应用程序”，再将旧应用移出该目录并从 Dock 移除旧图标，用新版重新固定。两份应用使用相同身份，长期并存可能让系统通知或 Dock 打开旧副本；应用文件名变化不改变数据目录，不要删除用户数据。

### 限制

- 不提供自动回滚或降级。强制关机、断电或安装过程被系统终止时不保证完成，下次启动以实际运行的版本为准。

## 提醒与更新检查

- 在串工具栏“更多 › 提醒”、订阅页或提醒页的行右键菜单中，可分别开启“全串更新”“PO 追更”“引用我的发言”，三者可以组合；开关本身不触发检查。
- 提醒以论坛回复数为基线（取舍见 [ADR 0001](docs/adr/0001-reminder-reply-count-baseline.md)）：全串更新与 PO 追更每次检查只读取对应模式（全部／只看 PO）的第 1 页，比较其 `ReplyCount` 与上次记下的值，增长多少就计多少，与串有多长无关；只开 PO 追更的串不读全部模式。开启后（包括关闭后再开启）的第一次检查只记下基线、不计数，关闭期间的回复不补。PO 的回复同时计入全串，两项分别显示。回复数包含之后被删除的回复，计数可能多于串里仍可见的新回复。
- 回复数变小时按本次值重设基线并提示，不计数；回复数缺失或结构异常时保持原基线并提示。串不存在、权限或网络失败只作为该串的覆盖问题提示，不关闭规则，也不删除已有计数。
- “引用我的发言”只读基线之后新增的页：开启后的第一次检查读取当前末页，记下已核对到的最后回复编号；之后只读从第一条未核对回复所在页到当前末页（按每页 19 条回复由回复数算出），编号更大的回复才算新回复，不从第 1 页扫描。新回复中明确引用（`>>No.`）的发言，先与发送记录里已确认的自己发言的编号比对，再用本机已存或本次读到的页面中该发言的饼干 ID，仍没有时用 `/api/ref` 读取；饼干 ID 与任一已导入饼干相同即算引用我，与被引者是否为 PO 无关，未引用的接话不算。一条回复引用多条我的发言只计一次。读不到被引发言或论坛未给饼干 ID 时提示“被引发言未能核实”，不当作不匹配；没有任何饼干带饼干 ID 时不读 `/api/ref`，只按已确认的发送匹配。导入、补填或修改饼干 ID 都不触发检查，只影响之后读到的回复。
- 后台请求逐个发出，相邻请求开始至少间隔 1 秒；前台阅读优先且不受该间隔限制。每串每批最多 5 次实际 HTTP 读取（含页、`/api/ref` 与匿名高页码探测），之后轮转到其他串；每轮最多 100 次。下一轮先查最久未检查的串，实际请求过的串即使失败或只查到一部分也会轮转，让本轮未覆盖的串优先；未完成的页与引用读取从断点接续，不回到第 1 页。某页读取失败或缺页时停在该页并提示“尚未补完”。
- 回复数（第 1 页）读取不带饼干；论坛返回权限类错误时，同一次检查内带饼干列表第一块饼干重读一次。读取新增页与 `/api/ref` 带这块饼干，避免无饼干时的第 100 页上限。没有导入饼干时所有请求都不带凭据。
- 后台自动检查默认每 15 分钟一次，每次额外加入 0–3 分钟随机抖动；在“设置 › 提醒”可选关闭／15／30／60 分钟。冷启动、明确从托盘／Dock／第二实例重新打开隐藏或已销毁的窗口、“手动检查”和定时检查，共用单次执行与 60 秒冷却。冷却与定时均用单调时钟，睡眠暂停计时、唤醒后继续剩余时间，不补跑；运行中或冷却中到点跳过，不排队。普通焦点变化和规则开关不触发检查。这里检查的是论坛回复，与软件版本更新无关。
- 遇到限流或验证码立即停止本轮，不重试、不换饼干绕过；之后间隔从设置值逐次翻倍，最长 120 分钟（仍加随机抖动），手动检查遇限流也一样。一轮全部成功后才恢复正常间隔；网络错误、取消或尚未查完不会解除退避。退避与本次限流的通知状态保存在本机，重启后保留。关闭自动检查时仍可手动检查，不安排自动重试。
- 同一次限流只提示一次：系统通知开启时同时发系统通知与应用内底部通知，关闭时只显示底部通知。底部通知显示预计重试时间，隐藏窗口时留到下次显示，保留至点击“知道了”或一轮全部成功；“知道了”只收起底部通知，不解除退避，提醒页仍显示状态。
- 导航“提醒”是与订阅页相同的串行列表，列出开启了至少一类提醒的串：有计数的串按最近一次增长时间排在前面，其余按最近开启时间。元信息按“全串、PO、引用”的顺序写出已开启且不为 0 的计数，如“全串:3 PO:2 引用:1”；有覆盖问题的行在元信息末尾显示警告图标，悬停或聚焦显示原因。标题行有“手动检查”（运行中或冷却中不可用，并提示剩余秒数）和上次检查时间。行右键菜单（也可用 ContextMenu 键／Shift+F10）提供“在新标签页打开”“复制串号”、“饼干颜色…”（本机有主帖时）、三项提醒开关和“清除提醒”。点击行按正常续读打开；该串没有阅读位置时，打开到基线之后第一条新回复所在的页（只有 PO 计数时用只看 PO）。
- 用户打开该串时三类计数一并清零：从任何列表、链接、引用跳转（包括在新标签页打开）或通知进入，或切换到正在显示该串的标签都算；在已显示的串里点击跳到同一串的引用（包括目标已在当前页面、只就地定位的情况）也算。悬停引用预览不算。启动时恢复的标签（包括当时的当前标签）在切换过去之前不清零；串显示期间检查到的新回复照常累计，下次打开、切回或在串内跳转引用时才清零。汐岛不记录逐条已读，清零只表示“已打开过该串”，不改阅读位置和访问记录。
- 一次检查结束或中断时，若有串的计数增加，默认发一条标题为“汐岛”、正文为“N 个串有新提醒”的系统通知，点击只打开窗口和提醒页，不触发另一次检查；没有增加时不通知。“设置 › 提醒 › 新提醒系统通知”关闭后只更新应用内计数与铃铛，不发系统通知，也不显示新提醒底部通知。macOS 还需在“系统设置 › 通知 › 汐岛”允许通知并选择横幅或提醒；应用内开关不能覆盖系统权限，专注模式也可能抑制显示。通知不可用或失败不影响应用内的计数。
- 在汐岛取消单项订阅或在同步中选择“两端都取消”时，不询问、也不改变本地提醒。外部取消、切换订阅来源、UUID 或网页绑定同样不会修改提醒；离线副本也独立。关闭某类提醒会删除该类的计数和基线，关闭前已在读取的结果不会再把它加回来。
- 删除历史（包括同时清除阅读进度）不改提醒规则、基线和计数。这些记录属于受保护的本机个人数据，不随普通缓存清理。
- 验证范围：本功能在 Linux WSLg 真实 Electron 中用隔离数据和受控论坛响应验证，计数与请求顺序另由受控 HTTP 测试核对；实现时对普通版面的一个串做过一次无饼干的第 1 页公开读取，确认可取得 `ReplyCount`。需要饼干才能浏览的版面上无饼干读取的行为未验证，由上述重读覆盖。Windows 托盘单击与 macOS Dock 点击重开已验证；两平台系统通知的实际显示与点击仍待原生验收。

## 历史、离线与缓存

- 导航“历史”打开整页，分为“浏览｜新串｜回复”三页。“离线”同样是整页，“草稿”仍为对话框；正在发送或确认是否已发出的草稿在草稿库中显示为已锁定，不能继续或删除，发送有结果后解锁（发出的不再留作草稿）。
- 普通串预览共用排版：饼干 ID 与时间、加粗标题和名称、最多约 20 行的正文、来源元信息与右侧缩略图。版面、时间线、App／网页订阅、历史浏览／新串／回复、离线、提醒和同步预览遵守同一正文规则；版面／时间线的置顶串保留紧凑样式。多行和空行保留，已解析的红绿字、加粗、引用和防剧透结构沿用正文的安全渲染；没有结构时按纯文字显示，不把文字里的 HTML 当标签执行。搜索保留自己的命中高亮与遮蔽，引用卡保留浮层操作。
- 单击行正文或 Enter 打开串，中键或 Ctrl/Cmd+单击在新标签页打开，右键（或聚焦后按 ContextMenu 键／Shift+F10）打开菜单。右侧缩略图独立打开原图，关闭后焦点回到缩略图。浏览页保留最近访问与离线标记，作者、时间、正文、回复数和附图只取本机尚存的数据，缓存清理后缺失字段保持未知，不为补齐预览请求论坛。
- 发送记录保留发送时固定的文字、标题、名称、身份、时间与投递目标，不被所属串主帖替代。已确认发言仍在本机时，正文结构和缩略图可复用这条发言；否则正文回退到发送原文，已回收的发送附图不承诺恢复。饼干 ID 是发送时本机记录的该饼干的饼干 ID，之后修改或移除饼干不影响；发送时还不知道饼干 ID 的记录显示该饼干现在的饼干 ID。元信息显示目标（版面名或“回复 No.串号”）与是否带图。单击“回复”行打开所在串，有串号时按引用定位规则跳到这条回复并可后退回历史；定位不到时按续读位置打开并注明。单击“新串”行打开该串；没有串号的新串打开所在版面列表。发送记录行的右键菜单为“在新标签页打开”“复制串号”：“回复”行复制这条回复自己的串号，“新串”行复制新串的串号；串号尚未确认的记录没有“复制串号”，不猜测、不联网补全。“新串”行的饼干 ID 就是串主的，有饼干 ID 时菜单还有“饼干颜色…”；“回复”行没有。
- 浏览历史保留到手动删除。浏览行右键菜单为“在新标签页打开”“复制串号”“饼干颜色…”（本机有主帖时）和“删除…”；单条删除和“清空历史…”都需要确认；“同时清除阅读进度”默认不勾选，不勾选时只删除访问记录。勾选后只有实际被删除访问记录的串清除阅读位置（清空历史时为当时历史中的串，不在历史中的串不受影响）；这些串已打开的阅读器会停止写回旧位置并回到开头，后退／前进也不会恢复清除前的位置；草稿和正在编辑的内容不受影响。删除历史不会删除离线副本、草稿或其他个人数据，也不是完整的隐私清除。
- “离线”页使用与订阅列表相同的串行（饼干 ID 与时间、标题、名称、摘要、版面／串号／回复数、缩略图），按首次保存时间从新到旧排列；更新副本不改变位置。行内容只取本机副本和缓存中尚存的主帖与最近保存页报告的回复数，不为补齐字段请求论坛；本机没有主帖时只显示串号和已知标题。正常完成的副本不显示状态；保存中、已取消、因错误停止、上次保存被中断或有原图未保存时，元信息末尾显示一个小图标，悬停或键盘聚焦该行时显示原因，原因同时是该行可访问名称的一部分。
- 离线页的行右键菜单（或聚焦后按 ContextMenu 键／Shift+F10）有“在新标签页打开”“复制串号”“饼干颜色…”（本机有主帖时）、“更新离线副本”“离线详情…”和“删除离线副本…”；中键或 Ctrl/Cmd+点击同样在新标签页打开。“更新离线副本”与离线副本窗口中的更新是同一操作（保存文字和原图），保存或删除进行中不可再次发起，行图标随进度刷新；未能开始时在该行下方说明原因。“离线详情…”打开与串工具栏“更多 › 离线保存”相同的离线副本窗口，关闭后焦点回到原行。
- 串工具栏“更多 › 离线保存”和 App／网页订阅行菜单的“离线保存…”打开同一个离线副本窗口。订阅行支持右键、ContextMenu 键和 Shift+F10，关闭后焦点回到原行；网页预览没有图片等字段也能按串号保存，不改变订阅集合、提醒或历史。同一串复用已有副本和任务，可查看、更新及删除。默认保存正文、回复和能取得的原图，可改为“仅文字”；缩略图不算原图。保存在后台逐页进行，可“取消保存”；窗口显示首次保存与最近更新时间、已保存的页、发言数、末尾候选（读取当时为空的页）、整个副本的原图“已保存 / 应保存”张数（最近一次为“仅文字”时另行注明，之前保存的原图仍计入），以及每张未保存原图的发言号和原因、读取失败的页与原因。只有保存进行中才定时刷新进度。
- 离线副本记录的是保存时能取得的内容，不是整串的完整快照。“更新离线副本”保留已有内容，只补充新取得的页面和原图；论坛上已删除或读取失败的内容不会从副本中移除。取消、读取失败、本地空间不足或应用退出时，已完成的部分保留，状态显示为“已取消”“因错误停止”或“上次保存被中断”。
- 行菜单和离线详情中的“删除离线副本…”都先确认，默认焦点在“取消”。确认后只移除该副本及其离线保护；文字、页面与原图转为普通缓存，历史、两个阅读模式的位置、订阅、提醒、草稿及发送记录保留。保存中删除会先停止并等待任务清理完成，期间不能重新保存同一串；取消确认不会停止保存。
- 删除后立即按既有近期使用顺序检查普通缓存额度，不保证优先淘汰刚删除的副本内容；额度为 0 时无其他保护的内容可立即淘汰。另一副本、草稿或当前阅读现场仍持有的内容继续受保护；尚存内容仍可阅读和搜索，搜索不再把它标为离线副本。所有离线列表同步移除该串，已打开的阅读器保持内容、模式和位置，不因删除刷新或联网。
- 停止或删除失败时保留副本并说明原因；副本已删但缓存额度检查失败时单独提示，不把两种结果混为一谈。删除不是隐私清除，不提供撤销；后续主动保存会建立新的首次保存时间，不能保证找回已淘汰或远端已删除的内容。删除流程已在 Linux WSLg 的隔离 Electron、受控网络下验证两处入口、并发保存、失败恢复及浅／深色 200% 缩放；不代表 Windows／macOS 原生验收。
- 普通缓存只包括浏览时已读取的文字和实际加载过的图片，不预取整串。默认上限 2 GB，在设置“存储与缓存”中以十进制 GB 填写（1 GB = 1,000,000,000 字节，可填小数，0 表示不保留普通缓存）。超过上限时先淘汰较久未使用的内容。
- 占用分开显示：可清理的文字（含派生的搜索数据）与图片按逻辑字节计入额度，共享的图片只计一次；正在打开的串、离线副本和草稿引用的内容受保护，与历史、阅读位置等个人记录分列，不计入可清理部分，也不会为满足上限被删除。受保护内容使占用无法回到上限以内时会说明。上限是逻辑额度，不限制整个数据目录的大小。
- “清理普通缓存…”在确认后只删除可清理的缓存。数据库文件大小单独显示（含索引与预写日志），清理后空间在库内复用，SQLite 文件不一定立刻缩小。

## 外观与阅读设置

设置是独立的工具标签，可从图标栏底部或 Ctrl/Cmd+, 打开；重复打开会激活已有的设置标签并保留浏览位置，不会新增一页。关闭设置标签（× 或 Ctrl/Cmd+W）返回此前的阅读标签，阅读位置和编辑内容保留。分区目录跟随滚动，窄窗改为固定在顶部的分区菜单；各处“打开设置”直达对应分区并聚焦标题。设置标签随工作区保存，重启后可以恢复。选项保存在本机数据库，重启后保留；界面缩放比例由 Electron 按页面保存，重启后同样保留。

切离设置时，未提交的饼干导入内容和 UUID 修改会清空；重新进入只读取已保存的 UUID。分区和滚动位置仍保留，临时分区菜单会关闭。

- **配色**：跟随系统、浅色或深色；另有“使用自定义主题”开关。内置浅色与深色主题中，正文、次要文字、链接、绿字、引用编号、警告与错误等普通文字与其所在的正文底、列表底、顶栏（透明，直接位于窗口底色及其晕染上）、磨砂导航／工具栏（按透明度叠加在窗口底色及其晕染上计算）、选中、悬停与提示底色之间的对比度均不低于 4.5:1。正文始终绘制在实底上，磨砂只用于导航、工具栏和浮层；对比度计算不考虑背景模糊。
- **自定义主题**：默认折叠，一套主题包含浅色、深色两组五种颜色（窗口底色、正文底色、正文文字、次要文字、强调色），外加名称、磨砂透明度（0.5–1）和圆角（0–20 像素）。启用后按上面的明暗选择（含跟随系统）使用对应一组；新建主题的两组分别取自内置浅色、深色配色，可各自修改。五种颜色由你决定，汐岛不检查它们之间的对比度，也不会改动；颜色不是 `#rrggbb` 或名称不合要求时，修改不会应用，对应输入框旁说明原因并保留你填写的值。绿字、警告、错误和引用编号等状态文字按所在一组的明暗生成，必要时向正文文字颜色靠拢。修改即时预览，点“保存”才写入，“放弃修改”或离开设置恢复原样。旧版本保存的单组自定义主题在读取时迁移：原基调那一组保留原颜色，另一组取自内置配色，原来选择的“自定义”变为开启自定义主题并保留原明暗。
- **阅读**：正文字体默认提供“系统无衬线／系统衬线”，可点“读取本机字体”后从已安装字体中选择；字号（13–28 像素）和阅读宽度（约 28–64 字，随字号缩放）适用于所有配色。窗口变窄时的留白、导航浮层与单栏阈值按实际宽度重新计算。
- **密度**：舒适为默认；紧凑只减少列表行、导航项、标签栏、工具栏和按钮的留白，不改变字号、配色或标签的分栏选择，可点击区域不小于 24×24 像素。
- **动态效果**：跟随系统或减少动态。减少动态时关闭过渡与动画；位置和状态的变化不依赖动画、闪烁或平滑滚动表达。手动刷新按钮（版面／时间线列表头部、“刷新订阅”、串末尾“刷新”、提醒页“手动检查”、编辑器“提交情况待核对”时的“重新核对”）在请求期间让 ↻ 图标旋转，请求很快结束也转满当前一圈；期间按钮标为忙碌，重复点击不发起新请求。减少动态时图标不旋转，只保留忙碌状态。
- **界面缩放**：50%–300%，可用快捷键或设置页中的按钮调整。已在 Linux 上以 200% 缩放、28 像素字号、64 字阅读宽度检查核心阅读流程与设置页可操作、无横向滚动或裁切。
- **提醒**：自动检查间隔可选关闭／15／30／60 分钟，默认 15 分钟；“新提醒系统通知”默认开启。两项即时保存，重启后保留，具体节奏与限流行为见上方“提醒与更新检查”。

### 界面偏好

图标栏的功能顺序与隐藏项、版块的收藏／隐藏／排序／分组收起状态、分栏列表宽度、自定义颜文字及“最近使用”的颜文字保存在 SQLite 的 `settings` 表中，重启后保留；缺失或损坏的值逐项回退默认值，不影响其他有效设置，不读取早期测试构建的浏览器存储值。自定义颜文字逐条保存内容与可选名称；旧版本保存的纯文字条目读作无名称，无效条目逐条忽略，其余照常显示，无需数据库升级。“最近使用”只保存内容，无效或重复的条目逐条忽略，最多读取 8 条。“设置 › 版块管理”可筛选、收藏、隐藏与排序版块：收藏和各普通版块组内可排序，时间线顺序固定，筛选时不能排序；版块面板的分组和“收藏”组均可收起，隐藏的筛选匹配单独显示“已隐藏 N 个匹配”，可用“显示”恢复。

“功能显示”、“版块管理”和饼干列表用同一种三横线（≡）排序手柄：按住手柄并移动超过 5px 开始拖动，插入线显示松开后的位置，松开即保存，按 Esc（或窗口失去焦点）取消并保持原顺序；只有手柄能拖起一行，行内的勾选框、收藏、隐藏等按钮照常点击。键盘聚焦手柄后按 Alt+↑／Alt+↓ 移动一位，首尾不再移动，焦点留在该手柄，并播报“第 n 项，共 m 项”。

只有主动点“读取本机字体”才调用 Local Font Access 并申请权限，单纯打开设置不会申请；该权限仅允许应用自己的主页面使用，官网登录窗口拒绝所有权限。

### 主题文件

“导入主题…／导出主题…”使用系统文件对话框；界面本身不能指定或读取任意文件路径。主题文件是 UTF-8 JSON（最大 64 KiB），只含数据，不含样式表或脚本：

```json
{
  "format": "xidao-theme",
  "version": 2,
  "name": "旧纸",
  "colors": {
    "light": { "background": "#efe6d6", "surface": "#fbf6ec", "text": "#2b2118", "secondaryText": "#5a4a3a", "accent": "#7a3e12" },
    "dark": { "background": "#1c1a17", "surface": "#24211d", "text": "#ece4d8", "secondaryText": "#c9bfb0", "accent": "#d9a066" }
  },
  "font": "serif",
  "fontSize": 18,
  "readingWidth": 38,
  "opacity": 0.7,
  "radius": 10
}
```

所有字段必填：颜色只接受 `#rrggbb`；`font` 为 `sans`、`serif` 或 `local:<字体名>`；数值范围同上（`fontSize`、`readingWidth`、`radius` 为整数）；名称 1–40 个字符，不含控制字符。导出使用版本 2；导入同时接受版本 1（单组颜色加 `base`，按上面的迁移规则补出另一组）。未知版本、未知字段或超出范围的文件会被拒绝并说明原因；颜色对比度不影响导入，当前主题和阅读参数保持不变。导入成功后，文件中的主题成为自定义主题并启用，字体、字号和阅读宽度一并应用。导出内容为自定义主题（尚未创建时为内置浅色、深色配色）加上当前阅读参数。

Windows／Linux 隐藏原生标题栏，保留系统窗口按钮，并通过主题化 `titleBarOverlay` 跟随当前主题与最上层颜色。设置与阅读标签共用顶栏和窗口底色，正文纸面从顶栏下方开始；模态打开时混合遮罩与当前表面，全窗图片查看器打开时使用查看器表面，关闭后恢复。取色位置按原生按钮区域与当前缩放换算。macOS 使用内嵌红绿灯按钮；顶部控件与原生按钮按中心对齐，左侧工具列与正文从标题带下方的同一基线开始，顶栏换行时一起下移。标签栏只预留超出左栏的安全区，附图全窗预览预留完整安全区，均按当前页面缩放换算；放大后控件高于原生按钮时优先保留完整点击区域。标签栏空白处可拖动窗口；窄窗或放大界面时工具按钮换行。Windows 11 已实际验证原生最小化／最大化、空白区拖动、交互控件非拖动、模态与预览的标题栏配色，以及 200% 下的预览按钮可达性；设置标签已验证深浅色共用顶栏。Apple Silicon 在设置标签改造前已人工验证红绿灯、全屏、拖动与 Dock 重开，并检查标题带在深浅色、舒适／紧凑密度及不同缩放下的布局；改造后的设置标签仍待 Mac 原生窗口验收。两平台的完整原生验收仍未完成。

### 可访问性范围

核心阅读流程与设置可只用键盘完成，控件有可读名称、角色与状态，焦点可见；选中项、当前导航项、无效输入等信息同时用文字、图标或形状表示，不只依赖颜色。以上为 Linux 下的实际界面检查与可计算对比度检查；尚未用 NVDA 或 VoiceOver 等读屏软件验证，也不宣称符合完整的 WCAG。

Windows 与 Apple Silicon macOS 原生中文输入法已人工验证本机搜索框与正文编辑框：空格选词、中英文切换、候选态 Enter／Esc，以及 Tab／Shift+Tab 焦点均正常；候选确认不提前搜索，取消组词不关闭编辑浮层，正文在组合结束后按 Enter 正常换行。正文检查使用无饼干的独立数据，未触发发送。

## 阅读位置

- 阅读位置按发言 ID、阅读线在该发言内的相对位置和距视口顶部的偏移保存，页码只用于先读取所在页。上方内容变高时保持阅读锚点。重新打开串时续读；可从“更多”或角落图标显式去开头／末尾。锚点不存在时退到该页编号相邻的已知发言，再退到页顶，并提示“原位置已变化，已返回附近”；读取失败显示错误与重试，不冒称恢复。全部回复与只看 PO 各自保存位置。
- 从中间页打开串（如末尾或跳页）时不显示主帖，也没有“加载上一页”按钮：用户向上滚动接近顶部时自动读取上一页并保持当前位置，读到第 1 页时主帖出现。初次到达不自动加载；读取失败时停止自动加载，显示一行原因与“重试”。读到串尾（最后一页是读到的空页，或按回复数已是末页）时，最后一页下方只保留“刷新”。
- 串内“刷新”（串末尾、“更多 › 刷新”或 Ctrl/Cmd+R，三者相同，进行中不会再发起第二次）从已显示的最后一个有回复的页重新读取；已读到串尾时继续读取其后的页，直到读到空页，所以落在前一页或新开一页的回复都会出现。未读到串尾时只重读当前最后一页，不预读后面的内容，向下滚动仍按需追加。新回复加在下方，不移动当前视口。某页联网读取失败时显示该页的本机缓存与原因并结束本次刷新；没有缓存时显示“刷新失败”与“重试”。
- 工具栏页码为 `x/y`，总页数未知时显示 `?`，展开后只有页码输入与“跳转”。开头／末尾角落按钮只由用户滚动触发：向上时出现在右上，向下时出现在右下；已在对应端时不出现，静止后隐藏，并留出通道避免遮挡正文。

## 图片

- 有附图的发言在正文里有一个固定大小的缩略图位置；缩略图只在接近可见区域时才读取，读取中、成功或失败都不改变发言高度，阅读位置不受影响。缩略图失败时在旁边说明原因并提供“重试”，不会自动反复重试；缩略图失败也仍可打开原图查看。
- 点击缩略图（或用键盘聚焦后按 Enter／空格）打开原图浮层，读取期间显示缩略图；原图失败时保留缩略图、说明原因并提供“重试”。关闭后焦点回到原缩略图，阅读位置不变；关闭后才到达的原图结果会被丢弃。
- 串列表（版面、时间线（含置顶串紧凑行）、订阅、提醒、离线、历史“浏览”）中，主帖有附图的行在右侧显示主帖缩略图（固定大小，裁切填满）。同样只在接近可见区域时读取，读取中或失败时显示占位框，不显示原因、不自动重试；行内文字位置不随图片到达而变化。点击缩略图（或在当前行按 Tab 到缩略图后按 Enter／空格）在列表上方打开该主帖的原图浮层，操作、保存与失败重试同阅读器；打开期间列表不可操作，关闭后焦点回到该缩略图（该行已不在列表中时回到列表）。原图只在打开浮层时读取，不预取。点行的其他位置照旧打开串；缩略图上的右键、中键与 Ctrl/Cmd+单击按整行处理。发送记录与搜索结果没有缩略图。
- 浮层操作：`+`／`-` 放大／缩小，`0` 适应窗口，`1` 原始大小，方向键（按住 Shift 加大步长）或拖动移动图片，滚轮以指针位置为中心缩放，Ctrl+S（macOS 为 Cmd+S）保存原图，Esc 关闭。
- “保存原图”只在原图已取得并显示后可用：通过系统保存对话框选择位置，写入的是本机保存的原图文件本身，文件扩展名按实际编码命名（例如论坛标为 `.png`、实际为 JPEG 的图片保存为 `.jpg`）。原图未取得时不会改存缩略图；写入先生成同目录临时文件再替换，失败时不改动已有文件。
- 图片只从 `https://image.nmb.best` 读取（缩略图 `thumb/`，原图 `image/`），请求不携带任何饼干、凭据或论坛身份，不跟随重定向，单张大小与像素数有安全上限。界面只能按“某条已读取发言的缩略图／原图”请求，不能指定网址或文件路径。
- 是否为图片只按文件内容判断（JPEG、PNG、GIF、WebP 的文件头及尺寸），不看论坛扩展名或响应的 `Content-Type`；SVG 等其他内容不接受。HTML 页面（包括以图片类型返回的错误页）、非 200 状态、跳转、内容中断都显示为对应的失败原因。失败只说明服务器这次返回了什么：论坛真实删图后的响应尚未核实，界面不会据此声称图片已被删除。实际解码在界面的沙箱进程中进行，无法解码的图片单独提示，重试时重新下载。

## 饼干

- “饼干”分区顶部的“打开官网饼干页”在系统浏览器打开 `https://www.nmbxd1.com/Member/User/Index/index.html`；导入区域在“官网导出｜userhash”两种方式间切换，用途标签紧邻饼干名称：
  - “官网导出”接受三种写法：二维码图片的整段地址（`https://publicapi.ovear.info/qrcode.php?…text=…`，汐岛只从中取出 `text` 参数，不访问该地址；其他参数忽略，别的网址会被拒绝）；`text=` 后面的值，即 `{"cookie": "<userhash>", "name": "<饼干 ID>"}` 的 Base64（标准或 URL 安全字母表，可含换行，可带地址中的百分号编码，如末尾的 `=` 写成 `%3D`）；或这段 JSON 本身（JSON 不做百分号解码，cookie 值原样使用）。内容中的 `name` 保存为饼干 ID；可选的“显示名称”只改汐岛内显示的名称，留空时显示名称即饼干 ID。
    - 获取方式：登录官网后进入饼干管理，打开某块饼干的“导出”页，右键复制二维码图片地址，整段粘贴即可；扫描该二维码得到的是 JSON。
    - 这一格式依据参考客户端源码（见文末致谢）。已用一份真实导出的图片地址 Base64 在 Windows 上实测：导入、加密保存、重新启动后解密均成功。另观察到真实图片地址形如 `qrcode.php?w=500&text=<Base64>&base64=1`，Base64 末尾的 `=` 写成 `%3D`；整段粘贴这样一份真实地址已在 Windows 上导入成功（单一样本），其余写法由合成值测试覆盖。扫码得到的 JSON 形式尚未用真实样本验证。内容中没有可用 `name` 的导出会被拒绝（缺少饼干 ID）。另用一块真实饼干的导出 Base64 核对过：导入后保存的饼干 ID 与该饼干在论坛发言旁显示的饼干 ID 一致（单一样本）。
  - “userhash”接受原始 userhash 值，可带 `userhash=` 前缀；必须填写这块饼干在发言旁显示的饼干 ID（最多 32 个字符，不含空格），显示名称可选，留空时同饼干 ID。
- “登录官网导入”在隔离的应用窗口打开官方登录页，由你输入邮箱、密码和验证码；汐岛不读取表单值。登录后列出账号饼干，勾选后“导入所选”，沿用粘贴导入的名称、重复检测与末尾追加规则。导入成功只表示格式可接受并已加密保存，不表示论坛当前接受这块饼干。
- 验证码图片可连续点击刷新。登录窗口仅允许官网固定验证码地址的 GET 图片请求，兼容官网每次追加的数字 `code` 缓存参数；这不开放其他账号路径、路由参数或第三方图片，也不改变表单隔离。
- 账号登录状态仅保存 `memberUserspapapa` 的系统保护密文与到期时间；不会保存密码、PHP 会话或读取系统浏览器的 Cookie。未到期时可重新打开列表，“退出登录”只删除本机登录状态，不请求官网退出。系统凭据保护不可用时不能登录；本地到期或服务端返回登录／跳转提示页时清除登录状态，需要重新登录。
- 账号读取只访问官方 HTTPS 饼干列表与导出页，分页去重、最多 20 页；结构变化或超过页数上限时报告无法识别，不把不完整内容当成空列表。导出页的二维码 `text` 参数在本机解析，不请求第三方二维码服务；应用、删除、领取与官网退出请求均被阻止。这些账号管理操作仍可在系统浏览器中的官网进行。
- 已在 Windows 使用一个真实账号验证应用内登录、连续刷新验证码、读取饼干列表、选择导入一块饼干及重启后保留本地记录；重启后仅使用系统保护的账号登录状态即可再次读取列表，无需重新登录，也不携带 `PHPSESSID`。此为单账号样本；真实多页列表、服务端会话过期及 macOS 真实账号流程仍待验收。
- 只接受可以安全放入 Cookie 头的字符（不含空格、分号、逗号、引号、反斜杠和控制字符），超长输入直接拒绝。错误提示按类别显示（为空、过长、链接不是官网导出二维码地址、不是 Base64 或 JSON、缺少 `cookie`、缺少饼干 ID、字符不可用），不会回显粘贴的内容。
- 再次导入已存在的 userhash（无论来自哪个入口）不修改其名称、顺序或任何用途选择：原条目没有饼干 ID 时补上导入内容中的 ID 并提示；ID 相同时只提示已有条目；ID 不同时保留原 ID，并提示两个 ID 不一致。
- 官网导出饼干含空格时的写法：原始值含空格的饼干，官网导出（以及“登录官网导入”读取的同一导出页）把空格写成 `+`，浏览器发送时写成 `%20`，论坛只接受后者。汐岛按导入时的原样保存，发送时（浏览、提醒检查、网页订阅读写、发言）统一把 `+` 换成 `%20` 放入 `Cookie: userhash=…`，其余字符原样发送（包括 `%7E` 这类百分号编码，不做解码）。重复检测也按换算后的写法比较，因此同一块饼干的导出写法与浏览器写法判为已有条目。已导入的饼干无需重新导入。依据为一块真实饼干（单一样本）：以导出写法发言被论坛拒绝；以浏览器写法发言成功；改为发送时换算后，用官网导出重新导入再发言也成功。请求头换算的各种情况另由本机受控 HTTP 测试覆盖。
- 饼干列表在每块饼干的显示名称下单独显示其饼干 ID；升级前导入、尚无 ID 的饼干显示“饼干 ID 未知”，照常用于浏览、发言与同步，但不参与“自己的发言”、PO 饼干和“引用我的发言”的识别。“填写 ID／修改 ID”可随时补填或修改，Esc 取消；修改只影响此后的识别，已有提醒不变。
- 饼干列表用排序手柄调整顺序，顺序保存在本机数据库中。浏览使用排在第一的饼干；只有列表为空时读取才不带饼干。新导入的饼干排在末尾。
- 默认发言饼干、网页同步对象分别保存，修改其中一项或调整顺序都不影响另一项。从旧版本升级时，原来选定的浏览饼干移到列表首位，其余按导入顺序排列；原来选择“不使用饼干”但已导入饼干的，升级后浏览改用列表第一块饼干。
- 移除饼干会删除其密文；正在使用它的用途显示为“已移除，需要重新选择”，不会自动改用其他饼干。移除排在第一的饼干后，浏览改用新的第一块。
- 读取失败（网络、权限、限流等）不会把饼干标记为失效。
- 本机数据库无法打开时，已保存的饼干与用途选择都无法读取：设置中显示饼干信息读取失败；由于无法确定浏览饼干，读取不会发出（不会当作“不使用饼干”），界面显示对应原因。

## 订阅

- 在设置中粘贴已有的 App UUID 后点“保存”，或明确点击生成新的 UUID；首次启动不自行生成。UUID 按系统凭据保护加密保存；设置页的输入框通过单独的接口取回已保存的 UUID 并显示，概览、操作记录和列表标签都不包含它。网页订阅使用“饼干 › 用途 › 网页同步对象”固定绑定的饼干，与浏览及默认发言身份独立。
- 导航“订阅”在当前标签打开列表，App｜网页切换只在页面顶部，另有“刷新订阅”；支持分栏阅读或关闭分栏后进入整页阅读。更换 UUID／网页绑定递增内部配置代次，只切换集合，保留旧远端集合与本地阅读资料；切换查看来源不修改代次或发言身份。
- 串工具栏的订阅按钮直接显示默认目标 App／网页；在“设置 › 订阅 › 串工具栏默认订阅到”选择并保存在本机，首次默认 App。订阅列表切换查看来源不改变它。按钮旁的箭头分别列出两端的订阅状态，可单次加入或取消所选端，不改变默认目标，也不影响另一端。默认端未配置时提供对应设置入口，不自动改投另一端；同时订阅两端仍使用“同步与合并”的预览。
- 打开页面后静默逐页读取，直到有效空页；不显示读取进度，错误、限流或验证码会停止，显示一行原因与“重试”。短页不算末页，缺失回复统计保持未知；有效空页仅是结束候选，不保证同一时刻的完整集合。认证错误、结构变化或缺页不当作空集合；已有观察保留。后台读取与回读共用一个通道，前台阅读优先；一次读取／连续核对任务有 20 秒时限，可停止排队和后续读取，不自动重试。
- 网页列表去掉页面自带的 `ID:` 前缀，正文按与 API 相同的安全规则保留允许结构；页面实际提供的有效论坛图片接入既有受控图片服务。未提供的图片信息和回复数保持未知，不为列表或同步预览额外读取每个串，也不预取原图。
- 串工具栏的主按钮及来源菜单、页面“加入”和行菜单“取消订阅”均在点击时向明确选定的一端直接写一次，不再确认、不自动重试；主进程先持久保存固定对象的意图再请求。行右键菜单还提供“在新标签页打开”“复制串号”“饼干颜色…”、三项提醒开关和“离线保存…”；离线操作见“历史、离线与缓存”。虽然论坛增删接口使用 GET，它们仍是显式写入，不由列表刷新、预取或重启触发。
- “服务端报告成功”和“回读看到存在／缺项”分别显示。重复调用可能仍报告成功，不表示每次改变了一项。取消的缺项结论必须有原有效观察、成功报告和从首页连续读至结束候选的回读；查找失败不算取消成功，分页期间外部变化仍可能影响观察。
- 操作记录仍持久保存当时的来源、身份引用、代次与前后证据，但页面不再列出操作记录。更换当前来源或绑定不改正在执行或待核对操作的对象。失败或未知结果在对应行显示一句原因与“核对订阅”；未列出的串显示在“加入”下方。“核对订阅”只读取原对象，绝不重发写入；重启也不重放、不补偿删除。旧饼干已移除或系统保护不可用时，原对象不能核对，不会替换身份。
- 写请求遇到限流或验证码时显示对应原因并停止自动回读，保留报告与待核对记录；之后只能由用户明确发起只读核对。
- 远端订阅与本地阅读及离线数据独立。取消订阅或在同步中选择“两端都取消”不询问、不改变本地提醒。
- 协议参考公开客户端资料及两端最小往返、重复操作的历史观察。客户端通过受控 HTTP、真实 SQLite 和 Electron 界面验证；真实 App 加入、单项同步到网页及两端刷新已通过人工验证，直接网页增删仍待人工验收。多页网页、失效身份、并发和故障恢复的证据为受控场景，不代表线上服务保证。

### 同步与合并

在“订阅”标题行点“同步与合并”，立即读取两端并显示差异；预览只读取，不写入。读取期间显示占位行；凭据或配置不可用时显示一行原因与“打开设置”。

- **差异**：比较当前 App UUID 与固定网页同步对象，把只在一端订阅的串分为“只在网页订阅（N）”“只在 App 订阅（N）”两组。每行与订阅页的串行相同（网页端没有图片与回复数时省略），可点按打开（分栏时在右侧阅读区），中键／Ctrl/Cmd+点击或右键“在新标签页打开”“复制串号”。
- **三种选择**：行尾为“两端都订阅｜两端都取消｜不动”。“两端都订阅”给缺少的一端加入；“两端都取消”从有的一端取消；“不动”这次不写。组标题可把整组设为“两端都订阅”或“不动”。界面不显示内部对象编号。
- **默认值**：汐岛记录了上次执行同步时两端共同存在的串（基线）。不在基线中的差异默认“两端都订阅”。在基线中、现在一端缺少的串默认“不动”，并在行内写明由来：本机在该串最近一次被确认共同存在之后，从缺少的一端成功取消过它（同一 UUID 与网页对象）时写“<时间> 在汐岛取消了 App 订阅／网页订阅”；否则写“上次同步后，App 订阅／网页订阅里不在了”。因此在订阅页单项取消后，下次同步可以选“两端都订阅”把它重新加回来。
- **读取不完整与首次同步**：任一端没有连续读到有效空页（缺页、认证错误、限流、验证或被停止）时，不判断基线中的缺失，全部差异按从未同步处理（默认“两端都订阅”），页面一行说明哪一端没有读完并提供“重试”。读取不完整或第一次同步（包括更换 UUID 或网页对象后）都不提供“两端都取消”，主进程也拒绝这类选择。缺项不证明用户主动删除，结束候选也不是一致快照。
- **执行**：底部按钮写出将发生的写入（如“执行：加入 3 · 取消 1”，全部“不动”时不可用），不再二次确认。写入前重新读取预览涉及的两端范围；身份、集合或页覆盖有变化时零写入，提示“订阅有变化，已重新预览”并刷新。这不是服务端锁或 CAS；检查通过后，其他客户端仍可能修改集合。
- 计划按预览顺序串行写入并逐项回读，行尾显示逐项进度与结果。服务端报告失败／未知或回读无法确认时停止后续写入；保留先前成功，不撤回、不补偿，也不把整批称为原子失败。“停止后续写入”只停止尚未开始的项目，不能撤销已发出的写请求。完成后回到订阅列表，顶部一行写结果（如“同步完成：加入 3，取消 1”，有失败或结果不明时加“查看”）；结果不明的项目只允许明确的只读“核对订阅”，继续处理须重新预览。
- **基线**：执行后基线为执行前基线加上本次复核时两端共同存在的串；确认加入的串进入基线，确认取消的串移出，“不动”的串保持原状态。逐项结果与对应基线在同一 SQLite 事务中保存。单看预览、订阅页的单项加入／取消都不写基线。
- **从旧 UUID 合并**：普通更换 UUID 只切换集合。在“设置 › 订阅”的 App 订阅 UUID 处点“从旧 UUID 合并…”，选择本机用过的旧 UUID，打开同一视图，列出旧集合中有、当前集合中没有的串，每行只有“加入｜不动”。此操作只加入当前集合，保留旧远端集合和本地阅读资料；旧 UUID 仍需要系统凭据保护可用。
- **同步记录**：标题行“更多 › 同步记录”只读列出每次同步或合并的逐项意图、报告与回读结果。重启将未完成计划标为中断，保留已确认项和待核对项，未开始项不执行。预览仅在本次进程有效，没有恢复执行旧计划的入口。

验证使用受控 App JSON／网页 HTML 服务、真实 SQLite 与 Electron 界面，覆盖首次同步、单项取消后重新同步、外部移除、读取不完整、执行前变化、部分成功、服务端提交后断线、结果保存故障及进程中断后重启；浅色／深色、紧凑密度与 200% 界面缩放在 Linux WSLg 演练。这些证据不替代 Windows／macOS 原生验收或真实论坛同步验证。

## 本机搜索与筛选

- 导航“搜索”、新标签的搜索入口和 Ctrl/Cmd+Shift+F 打开统一搜索页，默认“本机”，顶部可切换“联网”；各侧保留自己的查询与结果，切换不联网。本机一侧不提供当前串范围。阅读器“串内搜索”和 Ctrl/Cmd+F 打开“串内搜索”浮层，没有打开串时进入搜索页。每个标签保留自己的查询、筛选与结果。
- 只查本机仍保有的标题、正文和回复文字，包括普通缓存、离线副本，以及受保护订阅观察／操作记录中的帖子内容；不查草稿、饼干秘密、App UUID 或其他日志字段。结果标出普通缓存／离线副本／订阅记录来源。清理普通缓存后，仅由缓存保有的内容不再命中；离线与订阅记录仍保有的文字继续可查。
- 查询与索引使用 NFC 规范化和小写字面子串匹配。中文短词、引号、星号、百分号等均按原样处理，不解释为 SQL、正则或搜索表达式；标题和正文分别匹配，不跨字段拼接。至少三个 Unicode 字符先经 SQLite FTS5 trigram 找候选，再核对字面包含；一／二字符在所选范围内分批扫描。
- 提交后逐批读取，单批最多 64 条、每条摘录最多 240 字符；有更多内容时可“继续搜索”，查询期间可停止。新查询与关闭搜索会取消旧查询，迟到结果不会覆盖新结果。一次查询固定游标上界，不把查询期间新增的内容混入后续批次；重新提交可取得更新后的结果。
- 串内搜索首次打开时跟随当前全部／只看 PO 模式，也可在搜索面板中独立切换，不改变阅读模式。默认只搜索现有内容。“获取完整串并搜索”才从第 1 页开始后台逐页读取全部回复，使用普通缓存额度，不创建离线副本；可取消，显示实际取得的页、缺页、失败位置与末尾候选。结束候选不代表论坛的一致快照，获取过的内容也可能随后受缓存额度淘汰。
- 命中显示所属串及本机记录的页、模式和取得时间；没有位置证据时明确标注。点击复用引用定位规则：先核对再跳转，失败保留结果与阅读现场；重试成功只更新定位结果，之后由用户点击命中或“打开”跳转。PO 隐藏目标临时显示全部回复。每次跳转保存该步来源的查询、筛选、结果与命中焦点；连续搜索跳转后，“返回搜索结果”逐层恢复对应搜索和阅读模式。恢复较早结果不会重新获取内容；从空标签也可打开命中。
- 版面、时间线、订阅、历史与离线列表提供版面、日期和图片筛选：“筛选”是列表标题行里的图标按钮（在刷新左侧，启用时显示已启用项数），展开的字段紧接在标题下方；筛选生效时那里显示“显示 x / y 个串”、筛选范围与“清除筛选”。搜索页另有“发言：不限｜主帖｜回复”，计入已启用的筛选数：主帖指串号等于所属串号的发言，其余为回复；所属串未知的发言在选“主帖”或“回复”时都保留并标注。列表筛选没有这一项。列表按主帖字段，文字搜索按命中发言字段；日期比较论坛原始时间中的有效日历日期（服务端日历），不随本机显示时区换算。字段或覆盖未知的项目保留并标注，不当作确定不符合。筛选不会扫描整串，切换订阅来源或筛选不改当前阅读串。
- 索引不可用明确显示错误，不返回假空结果；可在界面重建和取消。重建分批整理本机内容，不联网或修改阅读记录；中断后索引保持不可用，重新启动或再次重建恢复。内容与搜索投影在同一事务更新／淘汰；派生逻辑字节按缓存或受保护归属计入占用，不等同 SQLite 文件的实际大小，清理后数据库文件不保证立即缩小。
- 本机搜索已在真实 Electron／SQLite 与受控 HTTP 数据上验证，包括长文字分批、取消、索引重建和保有来源清理；这不是 Windows／macOS 安装、原生密钥保护或真实论坛服务的验收声明。

## 阅读行为与限制

- 阅读使用 JSON 接口 `https://api.nmb.best/api/`（`getForumList`、`getTimelineList`、`showf`、`timeline`、`thread`、`po`、引用预览用的 `ref`），不跟随重定向，不自动重试。已导入饼干时，这些请求带饼干列表第一块的 `Cookie: userhash=…`；没有饼干时不带任何饼干或凭据。例外是提醒检查读取回复数的第 1 页：先不带饼干，遇到权限类错误才带这块饼干重读一次（见“提醒与更新检查”）。App 订阅使用同站 `/Api/feed`、`/Api/addFeed`、`/Api/delFeed` 的 UUID 参数，不带饼干；网页订阅仅向 `https://www.nmbxd1.com` 的固定列表／增删路径发送固定同步对象的饼干。两者均不跟随重定向。版面与时间线名称中的论坛标记只保留文字。
- 每次读取总时限 20 秒；按实际 `Content-Encoding` 解压，压缩前后体积均有上限。HTTP 200、HTML 页面或可解析的 JSON 本身都不视为成功：论坛返回的“该串不存在”等业务文本、HTML 错误页、结构不符都会显示为对应的失败类别（不存在、权限、限流或验证、网络、结构无法识别）。
- “末尾”在当前模式回复数已知时直接读取按回复数算出的末页；该页带回的回复数指向另一页时改读那一页，指向已读过的页时停止并显示“覆盖不足”。回复数未知时从第 1 页起有限探测，不下载全串。探测中途失败时显示已探测的页和失败位置，不会跳到估算页冒充末尾。
- 目录、串列表或串页中部分条目结构异常时，其余内容照常显示并提示未显示的条目数；全部不可用时按“结构无法识别”处理，不当作空列表，也不覆盖本机已有缓存。
- 论坛插入的 `Tips` 提示项不计为回复；同一页内重复的发言按发言 ID 去重。发言 ID 以十进制字符串保存，不受 JavaScript 数值精度影响。
- 正文由主进程解析为受限结构（文字、换行、强调、引用编号、绿字引用、红字、http/https 链接），界面不插入论坛 HTML，脚本、样式、事件属性和其他标签内容均被移除。`span`／`font` 上的内联样式只认三种：红色（`red`、`#f00`、`#ff0000`）显示为主题的错误色，绿色（`green`、`#789922`）与绿字引用相同，`font-weight: bold` 或 600 以上与加粗相同；大小写与空白不敏感，其他颜色、字号、背景等一律丢弃并保留文字。论坛原有的颜色值不会进入界面；纯文字、复制内容、搜索索引与发送核对都不含颜色和粗细。已缓存的正文按缓存时的解析结果显示，重新读取后才显示新的颜色与加粗。链接只能在系统浏览器中打开 http/https 地址。阅读正文、引用卡片、版规与时间线说明中的引用编号可预览与定位（见上文“引用”）；串列表摘要中的引用编号只作展示。
- 防剧透：正文中的 `[h]…[/h]` 在阅读正文、引用卡片和版规／说明里显示为遮挡块（按钮“显示隐藏内容”），单击或聚焦后按 Enter／Space 显示，显示后保持到该发言重新显示；串列表摘要和本机搜索（串内搜索与“本机”）的命中摘要中只显示不可操作的遮挡占位，命中词落在隐藏内容里时不标出，也不另加提示。搜索摘要从命中处前 60 字起截取 240 字，截取的起点或终点落在已配对的片段内时按完整正文补上标记，被截开的部分同样遮挡；被截成两半的标记不显示。片段可跨行，可包含引用编号（显示后照常预览与定位）、强调与绿字，两个标记也可分处不同格式之中（如从论坛以绿字显示的引用行开始）；每个 `[h]` 与其后阅读顺序上的第一个 `[/h]` 配对。未配对、内容只有空白的标记以及链接文字中的标记按原文显示（论坛不会把用户正文里的网址转成链接，链接文字中出现 `[h]` 的情形尚未见到）。遮挡只发生在显示层：本机保存的纯文字、搜索和发送核对仍是含 `[h]`、`[/h]` 的原文，标签与订阅标题也按原文截取。联网搜索的结果摘要来自第三方服务的网页摘要，汐岛不掌握其截取边界，按原文显示、不遮挡。
- 时间显示：发言头、引用预览、各类串行、历史、发送记录、草稿、离线详情、饼干导入与账号饼干、缓存与数据来源提示、搜索结果和订阅核对中的时间，都按本机时区显示为 `2026-10-26 13:12:00`，与本机今天同一天的只显示 `13:12:00`，不显示星期。论坛时间（发言的 `YYYY-MM-DD(星期)HH:MM:SS`、账号页的 `YYYY-MM-DD HH:MM:SS`）不带时区，按北京时间（UTC+8）解析后换算；本机记录的时间直接换算。无法识别的时间（含只有日期的账号页字段）按原文显示。例外：提醒页“上次检查”和限流重试时间只显示到分钟。提醒检查、发布核对和搜索日期筛选仍按论坛服务端时间与日历判断，不受显示时区影响。

## 联网搜索

论坛没有可用的站内全文搜索。汐岛的联网搜索只使用第三方服务 [nmb-search](https://nmb-search.166666666.xyz/) 的公开 JSON 接口，由汐岛自己的界面显示结果。该服务是基于 4get 的 Google CSE 代理，不是论坛官方搜索，也没有可用性承诺。

在统一“搜索”页顶部切到“联网”使用；界面只以一行说明查询交给第三方 nmb-search，并提供“打开搜索网站”。切换本机／联网不发送请求，各侧保留原有查询与结果。

- 只有按 Enter／点击“搜索”、翻到尚未取得的下一页、或在失败后点击“重试”／“重新搜索”时才联网；输入过程中、显示结果时都不发送请求，也不预取结果指向的论坛内容。没有自动重试，失败不会改用其他来源。
- 搜索词会交给该服务及其上游搜索引擎。收录可能不完整或过时；结果不代表论坛当前状态，摘要不是帖子正文，不进入本地内容。服务未提供日期时不显示日期。
- 请求只发往 `https://nmb-search.166666666.xyz/api/v1/web`：首次查询只带 `s=<搜索词>`，下一页只带服务返回的不透明令牌 `npt`。请求不携带论坛饼干或任何凭据，不跟随重定向；界面不能指定其他地址。常规日志不记录搜索词、完整查询地址或令牌。
- 每次请求总时限 20 秒，响应体积有上限。只有 `status` 为 `ok` 且结构有效的响应才算成功；`ok` 而结果为空显示“没有找到结果”，返回了条目却没有一条可用时按“无法识别的内容”处理。服务自己返回的错误说明会原样以文字显示，只有说明本身提到验证／验证码或请求过于频繁时才附加相应提示；HTTP 状态码（包括 429）只显示数字，不推断原因。网络失败、超时、网页或无法识别的内容分别说明。任何失败都不清除已显示的结果。
- 翻页：已取得的页在当前搜索页内随时可以回看，不再请求。根据服务文档，令牌使用一次或闲置 15 分钟即失效：汐岛只发送一次令牌，重复点击“下一页”只产生一个请求；取得令牌已满 15 分钟时不再发送，提示重新搜索；带令牌的请求失败、被取消或结果不明时，令牌视为已用，不会重放。最后一页没有令牌只表示没有可用的下一页，不表示收录完整。开始新的搜索会取代之前的查询链，之前迟到的结果不会覆盖新结果；新搜索失败或被取消时，之前已取得的页仍可前后查看，但不能再取新页。
- 搜索结果只在搜索页存在期间保存在内存中：该搜索页离开标签的所有历史（关闭标签、后退后走了别的路径）时释放，不保存搜索历史。
- 打开结果：只识别 `nmbxd1.com`、`nmbxd.com`（含 `www.`）上的 `/t/<串号>`（可带 `r=<发言号>`、`page=<页码>`）、`/Forum/po/id/<串号>.html`、`/f/<版面名>`、`/m/f/<版面名>`，以及时间线 `/Home/Forum/timeline/id/<编号>.html` 与 `/Forum/timeline/id/<编号>.html`（路径不区分大小写）。其他尚未取得样本的地址形态不识别。
  - 带 `r` 的链接（发言号可以是回复，也可以是主帖本身）先按本机记录定位（规则同引用定位）；本机没有记录或记录的页已不含该发言时，只读取链接所指的那一页（全部回复）核对编号。找到即跳转并高亮；该页没有这条发言时说明“未在该页找到”，可以“打开原串”：先读取该串续读位置所在的页，读到后才打开并记录历史，按正常续读位置阅读并注明未定位；读取失败时留在搜索页说明原因。串不存在、无权限或网络失败分别说明，重试只重新定位，不会自动补做跳转。
  - 只有串号的链接按正常续读位置打开该串；链接中的页码不作为阅读位置。PO 链接不改变该串的“全部／只看 PO”偏好。
  - 版面链接按版面目录中的名称匹配后打开该版面；目录中没有该名称时只提供在浏览器中打开。
  - 时间线链接按编号在本机时间线目录中查找，找到即在汐岛打开该时间线，标为“时间线 <名称>”（名称未知时为编号）；目录中没有该编号时在结果行内说明，不外开、不猜测。
  - 已识别的结果（串、回复、版面、时间线）在行尾有一个外链图标按钮“在浏览器中打开”；点卡片本身在汐岛内打开。未识别的其他 http/https 链接点卡片即交给系统浏览器，没有额外按钮；其他协议或带账号密码的地址不提供打开。标题与摘要始终作为纯文字显示。
  - 从结果打开的条目，工具栏后退按钮显示“返回搜索结果”，返回后恢复原来的页、滚动位置和焦点所在的结果。
- “打开搜索网站”在系统浏览器中打开同一服务的网站，可用于查看服务提示或人工验证；它不是故障时的备用来源，在浏览器里完成的验证也不会传回汐岛。
- 服务条款要求只用于人工触发的查询、不得密集抓取或在开发中反复发送测试查询。汐岛的自动测试只使用本地合成响应。
- 已验证范围：一次真实查询与一次真实下一页（成功结构、结果分类、只带令牌的翻页）。令牌过期、请求丢失、限流、验证与服务错误只用本地受控响应验证过客户端行为，未在真实服务上观察。

## 数据与安全

- 本机数据保存在 Electron 用户数据目录下的 `xidao.sqlite`，由主进程中的单个数据库 worker 访问（WAL、外键、短事务）。数据库结构单向升级；升级失败时回滚并保留原文件，不删除或重建数据库。用较旧版本打开由较新版本写入的数据库时，以只读方式读取并拒绝写入（此时也不能导入、重命名、移除饼干或修改用途）。
- SQLite schema v8 按实际表结构归并早期订阅、同步计划、草稿／发布、保留内容与工作区；v9 追加提醒，v10 追加搜索派生表、FTS5 trigram、事务投影与逻辑字节核算；v11 给饼干加入列表顺序，并把原“浏览饼干”用途并入顺序（原浏览饼干排到首位）。迁移单个事务完成并保留个人记录。已知早期 v2 且已有 `credentials` 表的数据库无法升级；早期独立搜索开发分支的同号 v8 库缺少这条历史所需的发布／工作区表，也会拒绝升级并保持原文件不变。升级前应备份数据库，不把版本号相同当成结构相同。
- SQLite schema v12 追加独立账号会话表，只接收非空 BLOB 密文与到期时间；账号会话不参与浏览／发言／网页订阅身份选择。v13 追加本机屏蔽表（串号或饼干标识），只在本机使用，不发送到论坛。v14 在同一迁移事务中删除串收藏、逐条已读记录与关注起点三张表，不迁移其中的数据；阅读位置、访问记录、提醒及其补查所用的页观察与末尾观察保留。v15 给饼干加入可空的饼干 ID 列（升级前的饼干为空），并删除“我的发言”记录表；发送尝试、结果状态与确认到的编号保留在发送记录中。
- v16 把提醒改为回复数基线：保留每条提醒规则、是否开启及其代次（原起点时间作为最近开启时间），删除旧的起点与水位、补查覆盖、检查轮次、逐事件提醒、通知登记和末尾观察，不做转换；新增按串、按提醒种类保存基线、已核对编号与计数的表，以及上次检查时间。升级后的第一次检查只为所有开启的规则重建基线、不计数。迁移在单个事务中完成，失败时原库保持不变；换回旧版本时不承诺能读取新的提醒数据。
- v17 给提醒检查器追加退避间隔、限流事件、已通知与已确认状态，保留 v16 的规则、基线与计数；迁移失败时在事务内回滚，不清空提醒。运行中写库失败时，当前进程仍保守延长限流间隔，确认或解除通知状态须写入成功后才生效；尚未写入的新退避不能保证在重启后保留。
- v18 删除草稿表的 E-mail 列，草稿的目标、饼干、标题、名称、正文、水印与附图保留；已有发送记录中保存的原始载荷不改写，其中的 E-mail 不再显示或使用。迁移在单个事务中完成，失败时原库保持不变；不承诺旧版本能读取升级后的数据库。
- v19 给发送尝试加入发送时的饼干 ID，并允许失败原因记为“可能已发出、核对未找到”；只有发送中与结果不明的尝试锁定来源草稿。已有尝试的饼干 ID 取升级时该饼干（本地编号不复用）已知的饼干 ID。SQLite 不能就地修改约束，因此在同一迁移事务中重建该表，保留全部尝试、编号与不复用的编号计数。迁移失败时回滚，原库保持不变。
- v20 新增饼干颜色表，保存饼干 ID、颜色名称与添加时间，并记下已自动分配过默认颜色的饼干 ID。升级时为已导入且饼干 ID 已知的饼干补分配一次默认颜色（添加时间取该 ID 最早的导入时间）；饼干 ID 未知的饼干不分配，之后补上 ID 时再分配。迁移在单个事务中完成，失败时原库保持不变。
- v21 给发送记录追加可空的论坛提示列（见“发布与确认”），已有记录不改写、读作没有论坛提示；单个事务完成，失败时原库保持不变。
- 从支持离线删除的 v15 数据库升级到 v17 时，已有离线副本和已转入普通缓存的内容沿用各自保留关系；已删除的副本不会因升级恢复。删除离线副本不清零提醒计数、不关闭规则，也不重置限流退避。升级前正常退出应用并备份用户数据目录；需要降级时恢复与旧版本匹配的升级前备份，不把旧程序读取新 schema 当作数据回滚。
- 阅读模式、阅读位置、访问记录和设置是个人记录，与缓存的论坛内容分开保存，不依赖缓存内容存在。汐岛不提供串收藏，也不记录已读／未读：没有首条未读、全部标为已读、未读数或“仅未读”筛选，订阅列表不显示新回复，追更请开启提醒。收藏版块（图标栏首字入口与版块管理）不受影响。自己的发言、PO 饼干与引用我的发言都只按饼干 ID 识别，不另存发言库。
- 读取到的图片保存在用户数据目录下的 `images/` 中，文件名由应用生成，数据库记录每个文件是缩略图还是原图、来源地址、取得时间、实际格式与尺寸，缩略图与原图分别记录。同一图片被多条发言或多个标签使用时只保存一份。
- 图片先完整写入临时文件，校验后改名到位，再提交数据库记录；中途失败、取消或写库失败时，已有的文件和记录保持不变，新文件被删除。正在显示图片的阅读视图会保护所用图片不被清理；清理只删除没有任何保护的记录及其文件，不会删除 `images/` 以外的文件，也不跟随符号链接。每次启动时会移除上次中断留下的临时文件和没有记录的文件。界面通过应用自己的 `xidao-image://` 地址读取这些文件，不暴露文件路径。
- 普通缓存的图片在超过额度或手动清理时按上面的规则删除；受保护（正在显示、离线副本引用、草稿副本）的图片不会被删除。
- 草稿保存在数据库中：每份草稿只有一个保存版本，目标、饼干引用、文字字段与附图引用在同一事务中一起替换；保存失败时上一个保存版本保持不变。饼干引用不随饼干移除而改写，移除后显示为“已移除”。各串记住的发言饼干同样只保存本地引用。
- 附图由主进程通过系统选择框读取所选文件，先复制为同目录临时文件，按文件内容确认是 JPEG、PNG、GIF 或 WebP 并检查尺寸，再改名为用户数据目录下 `draft-images/` 中的受管副本；所选原始文件只读不改。源文件不可读、不是图片、尺寸过大、磁盘空间不足都会作为失败说明，不留下临时文件。界面通过 `xidao-image://draft/…` 显示副本。
- 副本在被已保存草稿、打开中的编辑、仍可撤销删除的草稿或发送中／结果不明的发送尝试引用时受保护；没有任何引用时删除记录与文件。每次启动先恢复发送尝试，再清理无引用副本及中断留下的临时文件；尚未自动保存的编辑及其附图不跨重启保留。结果不明尝试的附件不会被启动清理移除。
- 饼干 userhash 通过 Electron `safeStorage` 的异步接口加密后存入数据库（Windows 为 DPAPI，macOS 为钥匙串）；数据库只保存显示名称、公开的饼干 ID、本地编号与密文。系统保护不可用时（包括 Linux 在没有密钥环服务时的 `basic_text` 后备）拒绝导入，已保存的饼干保持密文、不能用于读取，不会改用明文保存。系统保护防的是数据库文件被直接读取，不能防住以同一登录用户身份运行的其他程序。
- 解密后的 userhash 只在主进程内存中使用：界面只能取得显示名称、饼干 ID、来源、导入时间和用途选择；粘贴内容只在导入时经 IPC 传入主进程一次，导入成功或关闭设置后清空输入框。饼干只附加在主进程发往上述论坛接口的请求上，不写入 Chromium 会话 Cookie，因此界面加载的图片、外部链接等不会携带它。
- App UUID 使用相同的系统密钥保护器，数据库中只有本地引用和密文；更换后保留旧引用对应的密文供固定操作核对及显式合并，常规查询不返回秘密或秘密片段。观察、配置代次、逐项意图／报告、同步基线及计划历史保存在独立表中，不随读取失败清除。
- 发送意图和结果由数据库事务保存；确认结果、实际发言身份、来源草稿删除在同一事务中完成。意图保存失败时不会发送；发送后的结果写库失败则保留原意图，界面说明可能已经发出，重启按未知处理。发送记录保存正文与身份的本地编号，不保存解密后的 userhash。退出时如何收尾进行中的发送见上文“窗口、后台驻留与退出”。
- 界面页面启用 sandbox 与 context isolation，禁用 Node 集成与 webview，使用严格 CSP；不允许页面导航到其他地址或打开新窗口。权限仅为应用自己的主页面开放按需读取本机字体，其他权限均拒绝；官网登录窗口拒绝所有权限。界面只能调用少量具名操作，主进程校验调用页面（仅主窗口主框架中的应用页面）与参数，不提供任意网址、SQL 或文件访问。
- 剪贴板只经一个具名操作：对发起请求的窗口执行剪切、复制、粘贴、全选之一，或写入应用给定的纯文字（复制串号、复制内容、复制饼干、复制选中文字，长度有上限）。界面不读取剪贴板内容，粘贴由主进程直接作用于焦点所在的输入框；剪贴板权限没有因此对页面开放。
- 应用只运行一个实例；再次启动会唤起已运行的窗口。

## 开发

需要 Node.js 24 LTS 与 npm（版本见 `.nvmrc`；`.npmrc` 启用了 `engine-strict`）。

```bash
npm ci            # 安装锁定依赖
npm run dev       # 开发模式（热更新）
npm run build     # 构建到 out/
npm start         # 运行构建产物
npm run typecheck # 主进程、preload、共享代码与界面的类型检查
npm test          # Vitest，运行在 Electron 自带的 Node 中，与应用使用同一 SQLite 驱动
npm run dist:win  # 在 Windows 上构建 x64 NSIS 安装程序与 latest.yml 到 dist/
npm run dist:mac  # 在 macOS 上构建 x64／arm64 DMG 与 latest-mac.yml 到 dist/（DMG 由 hdiutil 生成，只能在 macOS 上构建）
```

打包配置见 `electron-builder.yml`：使用上游预编译 Electron，不编译 Chromium／Electron／Node；better-sqlite3 自带各平台的 N-API 预编译模块，打包时不需要编译原生代码。只打包 `out/`、`resources/icons/`、`package.json` 与 `LICENSE`。版本号取自 `package.json`；发布时把安装包与对应的 `latest.yml`（Windows）、`latest-mac.yml`（macOS，两种架构合在一个文件里）一起上传到 tag 为 `v<版本>` 的正式 GitHub Release，客户端依赖这些文件名与其中的 SHA-512。

`.github/workflows/macos-packages.yml` 在 GitHub 的 Apple Silicon macOS 机器上运行类型检查和测试，构建两种架构的 DMG，再用 `scripts/ci/mac-update-smoke.mjs` 检查：两个应用的 CPU 架构与 SQLite 原生模块、应用身份、图标、临时签名、`latest-mac.yml` 中的 SHA-512；Intel 版在 Rosetta 下能启动并读写数据；Apple Silicon 版安装后，用只在更新网络会话内应答的受控发布源走完缺少元数据时检查失败（不显示为已是最新）、发现新版、校验失败丢弃、自动下载、打开 DMG、退出、按用户方式替换应用、下次启动显示新版本并保留设置。结果不依赖仓库实际发布了哪些 Release。DMG、检查记录和应用输出作为工作流产物保留 14 天，不发布 Release。这些是自动化检查，不包括 Gatekeeper 首次打开提示与钥匙串授权等需要真人操作的环节。

代码结构：

| 位置 | 职责 |
| --- | --- |
| `src/shared/` | 共享类型与具名接口；`theme.ts`／`settings.ts` 统一配色、主题文件、内置色板对比度与设置校验 |
| `src/shared/search.ts`、`src/shared/online-search.ts` | 独立的本机检索与联网结果契约；两类搜索不共享请求或会话 |
| `src/main/forum/` | 论坛请求（限定来源与可携带饼干的来源、解压、体积与超时）、JSON 规范化与正文安全解析 |
| `src/main/identity/` | 饼干导入解析、系统密钥保护适配、用途选择与浏览身份解析 |
| `src/main/storage/` | 数据库 worker、迁移、覆盖计算、饼干密文与用途选择 |
| `src/main/reading/` | 前台／后台请求通道、读取与缓存回退、末尾有限探测 |
| `src/main/subscriptions/` | App JSON／网页 HTML 适配、UUID 保护、固定对象观察、预览／串行计划与逐项写入／回读恢复 |
| `src/main/images/` | 图片请求（限定来源、无凭据、不跟随重定向）、按文件内容识别格式、受管图片文件与保存 |
| `src/main/content/` | 历史清理、普通缓存额度与清理、离线副本的后台保存／更新与取消 |
| `src/main/search/` | 按窗口隔离的搜索会话、取消、分批重建与显式后台取串；索引与事务投影位于 `src/main/storage/search*.ts` |
| `src/main/online-search/` | 独立无凭据第三方请求、查询链、一次性分页令牌与内存页缓存 |
| `src/main/drafts/` | 草稿保存与删除、附图受管副本及其保护与回收、新编辑的发言饼干选择（串内选择优先于默认） |
| `src/main/publication/` | 发布预检、固定意图、单次 multipart 与回读确认、PO 提示和发送记录 |
| `src/main/reminders/` | 单次触发、单调定时与冷却、持久化退避、回复数基线比较、引用断点与请求预算、提醒通知 |
| `src/main/appearance.ts`、`src/main/zoom.ts` | 设置串行更新、受限主题导入导出、缩放与按键 |
| `src/main/updates/` | 固定来源的版本检查与下载（electron-updater、请求白名单、更新专用网络会话）、更新说明的安全解析、24 小时检查与就绪记录、退出安装与系统会话结束后的一次性启动安装 |
| `src/main/ipc.ts`、`src/preload/` | 具名 IPC 与调用方校验 |
| `src/renderer/` | React 界面 |

发布验证使用本地受控 HTTP、真实 SQLite／附件目录与 Electron 窗口：覆盖正文和附图、PO 三选择、失败存稿、响应丢失及结果落盘前进程中断，重启后无自动重投。单元／集成测试还覆盖总时限、重复入口、回读不符、数据库事务回滚和未知稿锁定。此范围不等于当前客户端在真实论坛的发布验收；线上写入仍须单独取得测试对象与额度授权。Linux 演练的合成密钥保护不证明 Windows DPAPI 或 macOS 钥匙串行为。

预览与页面交互的验证需使用 `npm run build` 的生产 CSS，而不只看开发热更新：同一组多行、空行、允许格式、防剧透、附图及缺失字段样本应覆盖上述列表入口，并检查浅／深色、舒适／紧凑、窄窗和 200% 缩放的代表组合。页面次要按钮需实走 Tab、点击、Enter、Space、表单回车和忙碌重复输入；草稿删除／撤销核对真实 SQLite 与附件，订阅离线入口核对同一副本和任务、回焦及订阅集合不变。受控网络记录用于确认历史／同步预览没有额外逐串读取或原图预取。这些应用层检查不代替 Windows／macOS 原生安装、升级、系统密钥保护及数据连续性验收。
