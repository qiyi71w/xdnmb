# 汐岛

汐岛是 [X 岛匿名版](https://www.nmbxd1.com/) 的第三方桌面客户端，基于 Electron、React、TypeScript 与本地 SQLite，目标平台为 Windows 10 / 11 x64 与 macOS 13+（Intel、Apple Silicon）。

> 项目处于早期开发阶段，目前实现了浏览阅读、阅读现场与外观设置；尚无安装包。

## 当前可用功能

- 左侧导航列出论坛提供的时间线与版面；版面显示版规，时间线显示说明。
- 串列表按页读取，滚动到底部时追加下一页并按串号去重。
- 串阅读：主帖与回复连续显示，接近底部时按需读取下一页；提供“开头”、“末尾”、“首条未读”、页码跳转和“刷新”。追加内容不移动当前视口。
- 每个串可在“全部”与“只看 PO”之间切换；选择按串保存，两种模式各自保存阅读位置。
- 多标签：每个标签有自己的后退／前进历史、当前版面、打开的串和分栏开关。分栏时列表与正文并排，单击列表项只更换正文，不增加后退步骤；关闭分栏时打开串会进入整页阅读并可后退回列表。
- 窄窗口：先收窄正文两侧留白，再把导航连续收窄为仍显示完整名称的紧凑栏，然后改为可展开的导航浮层，空间仍不足时暂用单栏（正文提供“返回串列表”）。正文字号与行距不随窗口改变；窗口变宽后恢复，手动关闭的分栏不会被重新打开。
- 阅读位置与已读状态，见下文“阅读位置与已读”。
- 每次读取的内容会保存到本机数据库。网络读取失败时，如本机有该页的已获取内容，会显示该缓存并标明获取时间与失败原因；没有缓存时显示失败原因和重试入口。
- 串的覆盖状态：已取得的页、缺页、结束候选页，以及服务端回复计数与实际取得条数是否一致；只看 PO 的页单独统计，不计入全部回复的覆盖。
- 外观与阅读设置：浅色、深色、跟随系统与自定义主题，正文字体／字号／阅读宽度，舒适／紧凑密度，减少动态效果，界面缩放；见下文“外观与阅读设置”。

尚未实现：退出后恢复标签与工作区、引用预览与跳转、图片缩略图与原图、发言与草稿、饼干、订阅、收藏、浏览历史列表、搜索、提醒、安装与更新。

## 快捷键

| 操作 | Windows／Linux | macOS |
| --- | --- | --- |
| 新标签／关闭当前标签 | Ctrl+T / Ctrl+W | Cmd+T / Cmd+W |
| 下一个／上一个标签 | Ctrl+Tab / Ctrl+Shift+Tab | Control+Tab / Control+Shift+Tab |
| 刷新当前内容（不重新载入应用） | Ctrl+R | Cmd+R |
| 当前标签后退／前进 | Alt+← / Alt+→ | Cmd+[ / Cmd+] |
| 打开设置 | Ctrl+, | Cmd+, |
| 界面放大／缩小／还原 | Ctrl+= 或 Ctrl++（含小键盘）/ Ctrl+- / Ctrl+0 | Cmd+= / Cmd+- / Cmd+0 |

后退／前进在输入框内不生效，不使用 Backspace 后退。打开设置与界面缩放在输入框内也可用，它们不占用文字编辑按键。Esc 只关闭最上层的设置窗口或导航浮层，并把焦点还给打开它的位置，不作为后退。设置中的“新标签默认开启分栏”初始为开启，只影响之后新建的标签。

## 外观与阅读设置

设置窗口（顶栏右侧按钮或 Ctrl/Cmd+,）中的选项都保存在本机数据库，重启后保留；界面缩放比例由 Electron 按页面保存，重启后同样保留。

- **配色**：跟随系统、浅色、深色或自定义。内置浅色与深色主题中，正文、次要文字、链接、绿字、引用编号、警告与错误等普通文字与其所在的正文底、列表底、顶栏（透明，直接位于窗口底色及其晕染上）、磨砂导航／工具栏（按透明度叠加在窗口底色及其晕染上计算）、选中、悬停与提示底色之间的对比度均不低于 4.5:1。正文始终绘制在实底上，磨砂只用于导航、工具栏和浮层；对比度计算不考虑背景模糊。
- **自定义主题**：可从当前生效的配色复制一份再修改名称、浅色／深色基调、五种颜色（窗口底色、正文底色、正文文字、次要文字、强调色）、磨砂透明度（0.5–1）和圆角（0–20 像素）。每次修改都会按与内置主题相同的文字／底色组合检查对比度；不达标或超出范围的修改不会应用，设置窗口列出具体组合与实际比值，输入框保留你填写的值，界面继续使用上次可用的主题。汐岛不会改动你选的五种颜色；绿字、警告、错误和引用编号等状态文字由汐岛按基调生成，必要时向正文文字颜色靠拢以保证可读。未通过检查的草稿在关闭设置窗口后不保留。
- **阅读**：正文字体（无衬线／衬线）、字号（13–28 像素）和阅读宽度（约 28–64 字，随字号缩放）适用于所有配色。窗口变窄时的留白、紧凑导航、浮层与单栏阈值按实际宽度重新计算。
- **密度**：舒适为默认；紧凑只减少列表行、导航项、标签栏、工具栏和按钮的留白，不改变字号、配色或标签的分栏选择，可点击区域不小于 24×24 像素。
- **动态效果**：跟随系统或减少动态。减少动态时关闭过渡与动画；位置和状态的变化不依赖动画、闪烁或平滑滚动表达。
- **界面缩放**：50%–300%，可用快捷键或设置窗口中的按钮调整。已在 Linux 上以 200% 缩放、28 像素字号、64 字阅读宽度检查核心阅读流程与设置窗口可操作、无横向滚动或裁切。

### 主题文件

“导入主题…／导出主题…”使用系统文件对话框；界面本身不能指定或读取任意文件路径。主题文件是 UTF-8 JSON（最大 64 KiB），只含数据，不含样式表或脚本：

```json
{
  "format": "xidao-theme",
  "version": 1,
  "name": "旧纸",
  "base": "light",
  "colors": { "background": "#efe6d6", "surface": "#fbf6ec", "text": "#2b2118", "secondaryText": "#5a4a3a", "accent": "#7a3e12" },
  "font": "serif",
  "fontSize": 18,
  "readingWidth": 38,
  "opacity": 0.7,
  "radius": 10
}
```

所有字段必填：颜色只接受 `#rrggbb`；`base` 为 `light` 或 `dark`；`font` 为 `sans` 或 `serif`；数值范围同上（`fontSize`、`readingWidth`、`radius` 为整数）；名称 1–40 个字符，不含控制字符。未知版本、未知字段、超出范围或对比度不达标的文件会被拒绝并说明原因，当前主题和阅读参数保持不变。导入成功后，文件中的主题成为自定义主题并切换到“自定义”，字体、字号和阅读宽度一并应用。导出内容为自定义主题（尚未创建时为当前生效的内置配色）加上当前阅读参数。

### 可访问性范围

核心阅读流程与设置可只用键盘完成，控件有可读名称、角色与状态，焦点可见；选中项、当前导航项、无效输入等信息同时用文字、图标或形状表示，不只依赖颜色。以上为 Linux 下的实际界面检查与可计算对比度检查；尚未用 NVDA 或 VoiceOver 等读屏软件验证，也不宣称符合完整的 WCAG。

## 阅读位置与已读

- 阅读位置按发言 ID、阅读线在该发言内的相对位置和距视口顶部的偏移保存，页码只用于先读取所在页。上方内容变高（如追加上一页、窗口变窄导致重排）时，阅读线保持在同一发言的同一位置。重新打开串时回到上次位置；“开头”“末尾”“首条未读”是显式入口。
- 发言只有在汐岛窗口获得焦点、没有设置窗口遮挡、当前标签正在显示正文、且可见高度达到“发言高度与正文视口高度中较小者”的一半，并连续保持 500 毫秒后才记为已读。窗口失焦、隐藏、打开设置窗口或切换标签会取消尚未满 500 毫秒的计时，重新满足条件后从头计时；已经记下的已读不会撤销。快速滚过、后台标签、列表预览和后台读取都不会产生已读；跳到末页不会把中间未读的页记为已读，只看 PO 时只会记录看到的 PO 回复。这是阅读判定，不代表已经读懂。
- “首条未读”和“全部标为已读”只作用于本机已经取得的发言；从未读取的页属于未知范围，不会被当作已读或未读计数。
- 关注起点（供后续的订阅、收藏、提醒使用）是首次开始关注的时刻，只建立一次，此后不随来源切换重置；起点之前已有的回复既不计为新回复，也不记为已读。论坛发言时间未经核实，回复属于起点哪一侧只按本机观察和“发言编号随时间递增”判断：编号不超过“开始关注时本机见过的最大发言编号”的是旧回复；如果起点之后本机看到过某个串的末尾（有回复的页及其后的空页），此后在该串出现的更大编号回复必定发表于起点之后，编号不小于它的回复（任何串）都计为新回复。两者都无法证明时保持“无法确定”，既不计为新回复也不当作已读。判断只使用正常阅读已取得的内容，不额外发起后台读取。

## 阅读行为与限制

- 只读取公开 JSON 接口 `https://api.nmb.best/api/`（`getForumList`、`getTimelineList`、`showf`、`timeline`、`thread`、`po`），请求不携带任何饼干或凭据，不跟随重定向，不自动重试。版面与时间线名称中的论坛标记只保留文字。
- 每次读取总时限 20 秒；按实际 `Content-Encoding` 解压，压缩前后体积均有上限。HTTP 200、HTML 页面或可解析的 JSON 本身都不视为成功：论坛返回的“该串不存在”等业务文本、HTML 错误页、结构不符都会显示为对应的失败类别（不存在、权限、限流或验证、网络、结构无法识别）。
- “末尾”按服务端回复数估算一页，再最多向后、向前各探测两页核实；未能核实时显示“覆盖不足”，探测中途失败时显示已探测的页和失败位置，不会跳到估算页冒充末尾，也不会下载全串。
- 目录、串列表或串页中部分条目结构异常时，其余内容照常显示并提示未显示的条目数；全部不可用时按“结构无法识别”处理，不当作空列表，也不覆盖本机已有缓存。
- 论坛插入的 `Tips` 提示项不计为回复；同一页内重复的发言按发言 ID 去重。发言 ID 以十进制字符串保存，不受 JavaScript 数值精度影响。
- 正文由主进程解析为受限结构（文字、换行、强调、引用编号、绿字引用、http/https 链接），界面不插入论坛 HTML，脚本、样式、事件属性和其他标签内容均被移除。链接只能在系统浏览器中打开 http/https 地址。引用编号目前只作展示。
- 帖子时间按论坛原文显示，时区未经核实。

## 数据与安全

- 本机数据保存在 Electron 用户数据目录下的 `xidao.sqlite`，由主进程中的单个数据库 worker 访问（WAL、外键、短事务）。数据库结构单向升级；升级失败时回滚并保留原文件，不删除或重建数据库。用较旧版本打开由较新版本写入的数据库时，以只读方式读取并拒绝写入。
- 阅读模式、阅读位置、已读记录、关注起点、访问记录和设置是个人记录，与缓存的论坛内容分开保存，不依赖缓存内容存在。
- 界面页面启用 sandbox 与 context isolation，禁用 Node 集成与 webview，使用严格 CSP；不允许页面导航到其他地址或打开新窗口，拒绝所有权限请求。界面只能调用少量具名操作，主进程校验调用页面与参数，不提供任意网址、SQL 或文件访问；主题导入／导出的文件只能由用户在系统对话框中选择，内容按上文规则校验后才会保存。
- 应用只运行一个实例。

## 开发

需要 Node.js 24 LTS 与 npm（版本见 `.nvmrc`；`.npmrc` 启用了 `engine-strict`）。

```bash
npm ci            # 安装锁定依赖
npm run dev       # 开发模式（热更新）
npm run build     # 构建到 out/
npm start         # 运行构建产物
npm run typecheck # 主进程、preload、共享代码与界面的类型检查
npm test          # Vitest，运行在 Electron 自带的 Node 中，与应用使用同一 SQLite 驱动
```

代码结构：

| 位置 | 职责 |
| --- | --- |
| `src/shared/` | 主进程与界面共享的数据类型、读取结果与具名接口；`theme.ts`／`settings.ts` 为内置配色、主题文件格式、对比度检查与设置校验的唯一来源 |
| `src/main/forum/` | 论坛请求（限定来源、解压、体积与超时）、JSON 规范化与正文安全解析 |
| `src/main/storage/` | 数据库 worker、迁移、覆盖计算 |
| `src/main/reading/` | 前台／后台请求通道、读取与缓存回退、末尾有限探测 |
| `src/main/appearance.ts`、`src/main/zoom.ts` | 设置的串行更新、主题文件导入导出、界面缩放与对应按键 |
| `src/main/ipc.ts`、`src/preload/` | 具名 IPC 与调用方校验 |
| `src/renderer/` | React 界面 |
