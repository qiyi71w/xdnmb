# 汐岛

汐岛是 [X 岛匿名版](https://www.nmbxd1.com/) 的第三方桌面客户端，基于 Electron、React、TypeScript 与本地 SQLite，目标平台为 Windows 10 / 11 x64 与 macOS 13+（Intel、Apple Silicon）。

> 项目处于早期开发阶段，目前提供浏览阅读、引用导航、图片查看、饼干管理、草稿、两端逐项订阅、收藏／历史／离线副本、缓存额度与本机／串内搜索；尚无安装包。

## 当前可用功能

- 左侧导航列出论坛提供的时间线与版面；版面显示版规，时间线显示说明。
- 串列表按页读取，滚动到底部时追加下一页并按串号去重。
- 串阅读：主帖与回复连续显示，接近底部时按需读取下一页；提供“开头”、“末尾”、“首条未读”、页码跳转和“刷新”。追加内容不移动当前视口。
- 每个串可在“全部”与“只看 PO”之间切换；选择按串保存，两种模式各自保存阅读位置。
- 多标签：每个标签有自己的后退／前进历史、当前版面、打开的串和分栏开关。分栏时列表与正文并排，单击列表项只更换正文，不增加后退步骤；关闭分栏时打开串会进入整页阅读并可后退回列表。
- 引用：正文中的引用编号悬停片刻或聚焦后按 Space 显示引用卡片（编号、复制编号、关闭始终可用）；鼠标移入卡片或焦点在卡片内时保持打开。单击或 Enter 定位并跳转，定位期间卡片显示“正在定位…”，正文不动；Ctrl+单击／Ctrl+Enter（macOS 为 Cmd）在后台新标签打开，新标签按“新标签默认开启分栏”且不复制原标签历史。只按本机已记录的所属串和观察页定位，不扫描全串：所属串未知时只能预览和复制；只知道原串时可“打开原串”，先读取该串续读位置所在的页，读到后才打开并记录历史，打开后持续注明未定位到该回复，读取失败则留在卡片上显示原因和重试；网络失败可手动重试，重试不会自动补做之前的跳转；服务端返回不存在与当前身份无权访问分别说明，显示缓存内容时标明获取时间与失败原因。失败卡片在鼠标移开后仍保留，直到关闭、点击外部、按 Esc 或另选引用。Esc 每次只关闭最上层的浮层（例如先关设置菜单，再关引用卡片）。
- 引用跳转与同一标签的后退／前进共用一套历史：跳转成功才记录来源串、列表、阅读位置、模式和触发的引用；当前条目来自引用时，工具栏后退按钮显示“返回引用处”，返回后焦点回到原引用编号。目标已在当前视口内时只短暂高亮，不新增历史。在列表中改选其他串后按钮恢复为普通后退，已有历史保留。
- 引用定位的依据与限制：论坛 `ref` 接口只返回发言内容，不给所属串或页码。定位只用本机读过的串页或列表中记下的所属串，再重新读取最近一次包含该回复的那一页核对编号（先按该串的模式偏好，再试另一模式）；本机没有任何记录时，只核对该编号本身是否为某串主帖。回复移页、只在列表里见过（此时先读取该串第 1 页确认可打开）或从未见过时不会猜测位置。只看 PO 页不含其他人的回复，因此只看 PO 时引用的非 PO 回复，若本机从未在全部回复页或列表中见过它，同样属于所属串未知。目标被只看 PO 隐藏时临时以全部回复显示，不改变该串的模式偏好，也不保存该临时显示的位置；返回时恢复原模式。
- 窄窗口：先收窄正文两侧留白，再把导航连续收窄为仍显示完整名称的紧凑栏，然后改为可展开的导航浮层，空间仍不足时暂用单栏（正文提供“返回串列表”）。正文字号与行距不随窗口改变；窗口变宽后恢复，手动关闭的分栏不会被重新打开。
- 阅读位置与已读状态，见下文“阅读位置与已读”。
- 图片：正文中的附图先显示缩略图，点击后在应用内查看、缩放和保存原图，见下文“图片”。
- 每次读取的内容会保存到本机数据库。网络读取失败时，如本机有该页的已获取内容，会显示该缓存并标明获取时间与失败原因；没有缓存时显示失败原因和重试入口。
- 串的覆盖状态：已取得的页、缺页、结束候选页，以及服务端回复计数与实际取得条数是否一致；只看 PO 的页单独统计，不计入全部回复的覆盖。
- 饼干管理（在“设置”中）：粘贴官网导出内容或原始 userhash 导入饼干，命名、重命名、移除，并分别选择浏览饼干、默认发言饼干与网页同步对象，见下文“饼干”。
- 发言编辑与草稿：在串底部准备回复、在版面底部准备新串，保存为本机草稿并从导航中的“草稿”继续或删除，见下文“发言编辑与草稿”。**发送尚未接入。**
- 收藏、浏览历史、离线副本与普通缓存额度：导航中的“收藏”“历史”“离线”打开列表并在当前标签阅读，设置中查看占用、调整上限和清理，见下文“收藏、历史、离线与缓存”。
- 订阅：设置受保护的 App UUID 与固定网页同步对象，切换两端列表、打开串，并显式加入／取消一项订阅；服务端报告与回读事实分别展示，见下文“订阅”。
- 本机与串内搜索、列表筛选：搜索仍保有的文字，按命中发言或主帖的字段筛选，并从搜索结果定位和返回，见下文“本机搜索与筛选”。

尚未实现：发送回复与新串、退出时统一保存未保存编辑、退出后恢复标签与工作区、订阅同步预览与合并搬运、删除离线副本、联网搜索、提醒、主题设置、安装与更新。

## 发言编辑与草稿

- 串正文底部与版面列表底部各有一条编辑栏，始终显示发言目标（“回复 No.…”／“在「版面」发新串”）与饼干；时间线没有发新串入口。还没有编辑时，栏中显示新编辑将使用的饼干：回复优先使用该串记住的选择，否则使用默认发言饼干；在设置中更换默认发言饼干后随之更新，但已有编辑不变。
- 点“回复”／“发新串”展开编辑：本标签已有该目标的编辑时恢复它，否则新建，不会自动套用草稿库中的旧稿。可填写正文（Enter 换行）、标题、名称、E-mail，附一张图片（添加／更换／移除；有图时可开关水印），选择发言饼干，并可“更改目标”（输入串号或从目录选版面）。改目标不换饼干，本标签随即打开新目标；本标签已有该目标的编辑时不改。
- 在回复编辑中选择饼干会同时记住为该串的选择；新串编辑中的选择只影响这份编辑；从草稿继续不会改写串的选择。饼干被移除后显示“已移除，需要重新选择”，不会改用默认饼干。
- 同一标签切到别的串或版面时，原编辑收起保留（文字、图片、目标、饼干），回来即恢复；各标签的编辑互不影响。Ctrl/Cmd+R 刷新与 Esc 都不会清空编辑。
- “保存草稿”（Ctrl/Cmd+S）保存焦点所在的编辑；焦点不在编辑中时保存当前标签可见且展开的编辑（正文优先于列表）。原图浮层打开时 Ctrl/Cmd+S 仍是保存原图。保存失败会说明原因，编辑内容不变。“放弃修改”对新编辑舍弃内容，对草稿只回到上次保存的版本（草稿本身保留）。
- 关闭标签（按钮或 Ctrl/Cmd+W）时，若该标签有未保存的编辑（包括切串后收起的），会列出它们并选择“保存并关闭”“放弃并关闭”或“取消”；任何一份保存失败都不会关闭，并列出失败项与原因。
- 导航中的“草稿”列出全部草稿（同一目标可有多份），显示目标、饼干、摘要、是否有图与保存时间。“继续”：该稿已在某个标签编辑时切到那个标签，否则在新标签打开原目标；正在编辑的草稿不能删除。附图保存为本机副本，不会改动所选的原始文件；重启后可从草稿恢复文字、饼干与图片，未保存的编辑不会跨重启保留。

## 收藏、历史、离线与缓存

- 串工具栏的“收藏”先读取该串当前是否已收藏，读到之前不可点；读取失败时显示“收藏状态未知”并可重试。收藏只保存入口，不会下载整串；首次收藏建立关注起点，取消后再收藏不会重置已建立的起点。在任一标签的工具栏或收藏列表中成功收藏或取消后，其他已打开的同串“收藏”按钮随即显示新的状态。
- 导航中的“收藏”“历史”“离线”打开同一个列表窗口，可在三者间切换。“打开”在当前标签以整页阅读打开该串（新增一步后退历史）；收藏列表可直接“取消收藏”。
- 浏览历史保留到手动删除。单条“删除…”和“清空历史…”都需要确认；确认中的“同时清除阅读进度与已读记录”默认不勾选，不勾选时只删除访问记录。勾选后只有实际被删除访问记录的串清除阅读位置和已读记录（清空历史时为当时历史中的串，不在历史中的串不受影响）；这些串已打开的阅读器会停止写回旧位置、中止尚未写完的“全部标为已读”并回到开头，后退／前进也不会恢复清除前的阅读位置；草稿和正在编辑的内容不受影响。删除历史不会删除收藏、离线副本、草稿或其他个人数据，也不是完整的隐私清除。
- 串工具栏的“离线保存”打开离线副本窗口。默认保存正文、回复和能取得的原图，可改为“仅文字”；缩略图不算原图。保存在后台逐页进行，可“取消保存”；窗口显示首次保存与最近更新时间、已保存的页、发言数、末尾候选（读取当时为空的页）、整个副本的原图“已保存 / 应保存”张数（最近一次为“仅文字”时另行注明，之前保存的原图仍计入），以及每张未保存原图的发言号和原因、读取失败的页与原因。只有保存进行中才定时刷新进度。
- 离线副本记录的是保存时能取得的内容，不是整串的完整快照。“更新离线副本”保留已有内容，只补充新取得的页面和原图；论坛上已删除或读取失败的内容不会从副本中移除。取消、读取失败、本地空间不足或应用退出时，已完成的部分保留，状态显示为“已取消”“因错误停止”或“上次保存被中断”。目前没有删除离线副本的入口。
- 普通缓存只包括浏览时已读取的文字和实际加载过的图片，不预取整串。默认上限 2 GB，在设置“存储与缓存”中以十进制 GB 填写（1 GB = 1,000,000,000 字节，可填小数，0 表示不保留普通缓存）。超过上限时先淘汰较久未使用的内容。
- 占用分开显示：可清理的文字（含派生的搜索数据）与图片按逻辑字节计入额度，共享的图片只计一次；正在打开的串、离线副本和草稿引用的内容受保护，与收藏、历史、阅读状态等个人记录分列，不计入可清理部分，也不会为满足上限被删除。受保护内容使占用无法回到上限以内时会说明。上限是逻辑额度，不限制整个数据目录的大小。
- “清理普通缓存…”在确认后只删除可清理的缓存。数据库文件大小单独显示（含索引与预写日志），清理后空间在库内复用，SQLite 文件不一定立刻缩小。

## 阅读位置与已读

- 阅读位置按发言 ID、阅读线在该发言内的相对位置和距视口顶部的偏移保存，页码只用于先读取所在页。上方内容变高（如追加上一页、窗口变窄导致重排）时，阅读线保持在同一发言的同一位置。重新打开串时回到上次位置；“开头”“末尾”“首条未读”是显式入口。保存的位置或返回的位置所在发言已不在该页时，退到该页编号相邻的已知发言，再退到该页顶部，并提示“原位置已变化，已返回附近”；该页读取失败时显示该页的错误和重试，不会当作已恢复而跳回串首。引用卡片和跳转后的高亮都不计为已读。
- 发言只有在汐岛窗口获得焦点、当前标签正在显示正文、且可见高度达到“发言高度与正文视口高度中较小者”的一半，并连续保持 500 毫秒后才记为已读。窗口失焦、隐藏或切换标签会取消尚未满 500 毫秒的计时，重新满足条件后从头计时；已经记下的已读不会撤销。快速滚过、后台标签、列表预览和后台读取都不会产生已读；跳到末页不会把中间未读的页记为已读，只看 PO 时只会记录看到的 PO 回复。这是阅读判定，不代表已经读懂。
- “首条未读”和“全部标为已读”只作用于本机已经取得的发言；从未读取的页属于未知范围，不会被当作已读或未读计数。
- 关注起点在首次观察到远端订阅或确认加入时建立（后续收藏、提醒也复用它），只建立一次，此后不随来源切换重置；起点之前已有的回复既不计为新回复，也不记为已读。论坛发言时间未经核实，回复属于起点哪一侧只按本机观察和“发言编号随时间递增”判断：编号不超过“开始关注时本机见过的最大发言编号”的是旧回复；如果起点之后本机看到过某个串的末尾（有回复的页及其后的空页），此后在该串出现的更大编号回复必定发表于起点之后，编号不小于它的回复（任何串）都计为新回复。两者都无法证明时保持“无法确定”，既不计为新回复也不当作已读。判断只使用正常阅读已取得的内容，不额外发起后台读取。

## 图片

- 有附图的发言在正文里有一个固定大小的缩略图位置；缩略图只在接近可见区域时才读取，读取中、成功或失败都不改变发言高度，阅读位置不受影响。缩略图失败时在旁边说明原因并提供“重试”，不会自动反复重试；缩略图失败也仍可打开原图查看。
- 点击缩略图（或用键盘聚焦后按 Enter／空格）打开原图浮层。浮层只覆盖当前串的正文，读取原图期间显示缩略图；原图失败时保留缩略图、说明原因并提供“重试”。浮层打开期间正文被遮住，不会产生已读；关闭后焦点回到原缩略图，阅读位置不变；关闭后才到达的原图结果会被丢弃。
- 浮层操作：`+`／`-` 放大／缩小，`0` 适应窗口，`1` 原始大小，方向键（按住 Shift 加大步长）或拖动移动图片，滚轮以指针位置为中心缩放，Ctrl+S（macOS 为 Cmd+S）保存原图，Esc 关闭。
- “保存原图”只在原图已取得并显示后可用：通过系统保存对话框选择位置，写入的是本机保存的原图文件本身，文件扩展名按实际编码命名（例如论坛标为 `.png`、实际为 JPEG 的图片保存为 `.jpg`）。原图未取得时不会改存缩略图；写入先生成同目录临时文件再替换，失败时不改动已有文件。
- 图片只从 `https://image.nmb.best` 读取（缩略图 `thumb/`，原图 `image/`），请求不携带任何饼干、凭据或论坛身份，不跟随重定向，单张大小与像素数有安全上限。界面只能按“某条已读取发言的缩略图／原图”请求，不能指定网址或文件路径。
- 是否为图片只按文件内容判断（JPEG、PNG、GIF、WebP 的文件头及尺寸），不看论坛扩展名或响应的 `Content-Type`；SVG 等其他内容不接受。HTML 页面（包括以图片类型返回的错误页）、非 200 状态、跳转、内容中断都显示为对应的失败原因。失败只说明服务器这次返回了什么：论坛真实删图后的响应尚未核实，界面不会据此声称图片已被删除。实际解码在界面的沙箱进程中进行，无法解码的图片单独提示，重试时重新下载。

## 饼干

- 两个导入入口分开处理：
  - “官网导出内容”接受 `{"cookie": "<userhash>", "name": "<名称>"}` 这段 JSON，或它的 Base64（标准或 URL 安全字母表，可含换行）。名称留空时使用内容中的 `name`。
    - 获取方式：登录官网后进入饼干管理，打开某块饼干的“导出”页。扫描页面上的二维码得到这段 JSON；或者复制二维码图片地址，取 `text=` 参数的值，即其 Base64。
    - 这一格式依据参考客户端源码（见文末致谢）。已用一份真实导出的图片地址 Base64 在 Windows 上实测：导入、加密保存、重新启动后解密均成功。扫码得到的 JSON 形式尚未用真实样本验证；若粘贴的值仍带百分号编码（如 `%2B`），会被判为格式无法识别。
  - “原始 userhash”接受 userhash 值，可带 `userhash=` 前缀，必须填写名称。
- 导入成功只表示格式可接受并已加密保存，不表示论坛当前接受这块饼干；汐岛不登录、不领取、不导出饼干，也不读取浏览器中的 Cookie。
- 只接受可以安全放入 Cookie 头的字符（不含空格、分号、逗号、引号、反斜杠和控制字符），超长输入直接拒绝。错误提示按类别显示（为空、过长、不是 Base64 或 JSON、缺少 `cookie`、字符不可用），不会回显粘贴的内容。
- 再次导入已存在的 userhash（无论来自哪个入口）只提示已有条目，不修改其名称或任何用途选择。
- 浏览饼干、默认发言饼干、网页同步对象分别保存，修改其中一项不影响另外两项。
- 移除饼干会删除其密文；正在使用它的用途显示为“已移除，需要重新选择”，不会自动改用其他饼干。浏览饼干处于这种状态时，读取不会发出（也不会改为不带饼干发出），界面提示到设置中重新选择；如本机有缓存则显示缓存并说明原因。
- 读取失败（网络、权限、限流等）不会把饼干标记为失效。
- 本机数据库无法打开时，已保存的饼干与用途选择都无法读取：设置中显示饼干信息读取失败；由于无法确定浏览饼干，读取不会发出（不会当作“不使用饼干”），界面显示对应原因。

## 订阅

- 在设置中粘贴已有的 App UUID，或明确点击生成新的 UUID；首次启动不自行生成。输入默认遮蔽，保存后清空，界面只显示本机引用，不返回已保存的 UUID。网页订阅使用“饼干 › 用途 › 网页同步对象”固定绑定的饼干，与浏览及默认发言身份独立。
- 导航“订阅的串”在当前标签打开列表，可切换 App／网页来源、分栏阅读或关闭分栏后进入整页阅读。设置与列表标明来源、对象及配置代次。更换 UUID／网页绑定递增代次，只切换集合，保留旧远端集合与本地阅读资料；切换查看来源不修改代次或发言身份。
- 列表逐页读取，明确显示取得时间、已读页范围和后续未读范围；短页不算末页，缺失回复统计保持未知。有效空页仅是结束候选，不保证同一时刻的完整集合。认证错误、结构变化或缺页不当作空集合；已有观察保留并标明时效。后台读取与回读共用一个通道，前台阅读优先；一次读取／连续核对任务有 20 秒时限，可停止排队和后续读取，不自动重试。
- 可以按串号加入、加入当前阅读的串，或取消某个列表项。确认时显示固定对象，主进程先持久保存意图再请求。虽然论坛增删接口使用 GET，它们仍是显式写入，不由列表刷新、预取或重启触发。
- “服务端报告成功”和“回读看到存在／缺项”分别显示。重复调用可能仍报告成功，不表示每次改变了一项。取消的缺项结论必须有原有效观察、成功报告和从首页连续读至结束候选的回读；查找失败不算取消成功，分页期间外部变化仍可能影响观察。
- 操作记录保留当时的来源、身份引用、代次与前后证据。更换当前来源或绑定不改正在执行或待核对操作的对象。响应丢失、写入后的结果保存中断或核对失败时明确保留不确定性；当前请求结束且存储恢复后，可直接在操作记录中核对，无需重启。“核对”只读取原对象，重启不重放写入，也不补偿删除。旧饼干已移除或系统保护不可用时，原对象不能核对，不会替换身份。
- 写请求遇到限流或验证码时显示对应原因并停止自动回读，保留报告与待核对记录；之后只能由用户明确发起只读核对。
- 远端订阅与本地阅读、收藏及离线数据独立。当前没有提醒规则，不额外询问提醒处理；同步预览、合并搬运与提醒联动尚未实现。
- 协议参考公开客户端资料及两端最小往返、重复操作的历史观察。当前客户端通过受控 HTTP、真实 SQLite 和 Electron 界面验证；本版本尚未对真实论坛执行身份读取／订阅增删 smoke。多页网页、失效身份、并发和故障恢复的证据为受控场景，不代表线上服务保证。

## 本机搜索与筛选

- 导航“搜索”、新标签的“搜索本机内容”和 Ctrl/Cmd+Shift+F 打开本机搜索；阅读器“串内搜索”和 Ctrl/Cmd+F 打开当前串搜索，没有打开串时进入本机搜索。每个标签保留自己的查询、筛选与结果。
- 只查本机仍保有的标题、正文和回复文字，包括普通缓存、离线副本，以及受保护订阅观察／操作记录中的帖子内容；不查草稿、饼干秘密、App UUID 或其他日志字段。结果标出普通缓存／离线副本／订阅记录来源。清理普通缓存后，仅由缓存保有的内容不再命中；离线与订阅记录仍保有的文字继续可查。
- 查询与索引使用 NFC 规范化和小写字面子串匹配。中文短词、引号、星号、百分号等均按原样处理，不解释为 SQL、正则或搜索表达式；标题和正文分别匹配，不跨字段拼接。至少三个 Unicode 字符先经 SQLite FTS5 trigram 找候选，再核对字面包含；一／二字符在所选范围内分批扫描。
- 提交后逐批读取，单批最多 64 条、每条摘录最多 240 字符；有更多内容时可“继续搜索”，查询期间可停止。新查询与关闭搜索会取消旧查询，迟到结果不会覆盖新结果。一次查询固定游标上界，不把查询期间新增的内容混入后续批次；重新提交可取得更新后的结果。
- 串内搜索首次打开时跟随当前全部／只看 PO 模式，也可在搜索面板中独立切换，不改变阅读模式。默认只搜索现有内容。“获取完整串并搜索”才从第 1 页开始后台逐页读取全部回复，使用普通缓存额度，不创建离线副本，也不标已读；可取消，显示实际取得的页、缺页、失败位置与末尾候选。结束候选不代表论坛的一致快照，获取过的内容也可能随后受缓存额度淘汰。
- 命中显示所属串及本机记录的页、模式和取得时间；没有位置证据时明确标注。点击复用引用定位规则：先核对再跳转，失败保留结果与阅读现场；重试成功只更新定位结果，之后由用户点击命中或“打开”跳转。PO 隐藏目标临时显示全部回复。每次跳转保存该步来源的查询、筛选、结果与命中焦点；连续搜索跳转后，“返回搜索结果”逐层恢复对应搜索和阅读模式。恢复较早结果不会重新获取内容；从空标签也可打开命中。
- 版面、时间线、订阅、收藏／历史／离线列表提供版面、日期和图片筛选；订阅和收藏另有仅未读。列表按主帖字段，文字搜索按命中发言字段；日期比较论坛显示的有效日历日期，不猜测时区。字段或覆盖未知的项目保留并标注，不当作确定不符合。筛选不会扫描整串，切换订阅来源或筛选不改当前阅读串。
- 索引不可用明确显示错误，不返回假空结果；可在界面重建和取消。重建分批整理本机内容，不联网或修改阅读记录；中断后索引保持不可用，重新启动或再次重建恢复。内容与搜索投影在同一事务更新／淘汰；派生逻辑字节按缓存或受保护归属计入占用，不等同 SQLite 文件的实际大小，清理后数据库文件不保证立即缩小。
- 本机搜索已在真实 Electron／SQLite 与受控 HTTP 数据上验证，包括长文字分批、取消、索引重建和保有来源清理；这不是 Windows／macOS 安装、原生密钥保护或真实论坛服务的验收声明。

## 阅读行为与限制

- 阅读使用 JSON 接口 `https://api.nmb.best/api/`（`getForumList`、`getTimelineList`、`showf`、`timeline`、`thread`、`po`、引用预览用的 `ref`），不跟随重定向，不自动重试。选择了浏览饼干时，这些请求带 `Cookie: userhash=…`；未选择时不带任何饼干或凭据。App 订阅使用同站 `/Api/feed`、`/Api/addFeed`、`/Api/delFeed` 的 UUID 参数，不带饼干；网页订阅仅向 `https://www.nmbxd1.com` 的固定列表／增删路径发送固定同步对象的饼干。两者均不跟随重定向。版面与时间线名称中的论坛标记只保留文字。
- 每次读取总时限 20 秒；按实际 `Content-Encoding` 解压，压缩前后体积均有上限。HTTP 200、HTML 页面或可解析的 JSON 本身都不视为成功：论坛返回的“该串不存在”等业务文本、HTML 错误页、结构不符都会显示为对应的失败类别（不存在、权限、限流或验证、网络、结构无法识别）。
- “末尾”按服务端回复数估算一页，再最多向后、向前各探测两页核实；未能核实时显示“覆盖不足”，探测中途失败时显示已探测的页和失败位置，不会跳到估算页冒充末尾，也不会下载全串。
- 目录、串列表或串页中部分条目结构异常时，其余内容照常显示并提示未显示的条目数；全部不可用时按“结构无法识别”处理，不当作空列表，也不覆盖本机已有缓存。
- 论坛插入的 `Tips` 提示项不计为回复；同一页内重复的发言按发言 ID 去重。发言 ID 以十进制字符串保存，不受 JavaScript 数值精度影响。
- 正文由主进程解析为受限结构（文字、换行、强调、引用编号、绿字引用、http/https 链接），界面不插入论坛 HTML，脚本、样式、事件属性和其他标签内容均被移除。链接只能在系统浏览器中打开 http/https 地址。阅读正文中的引用编号可预览与定位（见上文“引用”）；串列表摘要和引用卡片内的引用编号只作展示。
- 帖子时间按论坛原文显示，时区未经核实。

## 数据与安全

- 本机数据保存在 Electron 用户数据目录下的 `xidao.sqlite`，由主进程中的单个数据库 worker 访问（WAL、外键、短事务）。数据库结构单向升级；升级失败时回滚并保留原文件，不删除或重建数据库。用较旧版本打开由较新版本写入的数据库时，以只读方式读取并拒绝写入（此时也不能导入、重命名、移除饼干或修改用途）。
- 阅读模式、阅读位置、已读记录、关注起点、访问记录和设置是个人记录，与缓存的论坛内容分开保存，不依赖缓存内容存在。
- 读取到的图片保存在用户数据目录下的 `images/` 中，文件名由应用生成，数据库记录每个文件是缩略图还是原图、来源地址、取得时间、实际格式与尺寸，缩略图与原图分别记录。同一图片被多条发言或多个标签使用时只保存一份。
- 图片先完整写入临时文件，校验后改名到位，再提交数据库记录；中途失败、取消或写库失败时，已有的文件和记录保持不变，新文件被删除。正在显示图片的阅读视图会保护所用图片不被清理；清理只删除没有任何保护的记录及其文件，不会删除 `images/` 以外的文件，也不跟随符号链接。每次启动时会移除上次中断留下的临时文件和没有记录的文件。界面通过应用自己的 `xidao-image://` 地址读取这些文件，不暴露文件路径。
- 普通缓存的图片在超过额度或手动清理时按上面的规则删除；受保护（正在显示、离线副本引用、草稿副本）的图片不会被删除。
- 草稿保存在数据库中：每份草稿只有一个保存版本，目标、饼干引用、文字字段与附图引用在同一事务中一起替换；保存失败时上一个保存版本保持不变。饼干引用不随饼干移除而改写，移除后显示为“已移除”。各串记住的发言饼干同样只保存本地引用。
- 附图由主进程通过系统选择框读取所选文件，先复制为同目录临时文件，按文件内容确认是 JPEG、PNG、GIF 或 WebP 并检查尺寸，再改名为用户数据目录下 `draft-images/` 中的受管副本；所选原始文件只读不改。源文件不可读、不是图片、尺寸过大、磁盘空间不足都会作为失败说明，不留下临时文件。界面通过 `xidao-image://draft/…` 显示副本。
- 副本在被某份已保存草稿引用、或被某个打开中的编辑显示时受保护；两者都没有时（如删除草稿、编辑换图后放弃、关闭编辑）删除其记录与文件。每次启动时，没有草稿引用的副本和中断留下的文件会被移除；未保存的编辑及其附图不跨重启保留。
- 饼干 userhash 通过 Electron `safeStorage` 的异步接口加密后存入数据库（Windows 为 DPAPI，macOS 为钥匙串）；数据库只保存名称、本地编号与密文。系统保护不可用时（包括 Linux 在没有密钥环服务时的 `basic_text` 后备）拒绝导入，已保存的饼干保持密文、不能用于读取，不会改用明文保存。系统保护防的是数据库文件被直接读取，不能防住以同一登录用户身份运行的其他程序。
- 解密后的 userhash 只在主进程内存中使用：界面只能取得名称、来源、导入时间和用途选择；粘贴内容只在导入时经 IPC 传入主进程一次，导入成功或关闭设置后清空输入框。饼干只附加在主进程发往上述论坛接口的请求上，不写入 Chromium 会话 Cookie，因此界面加载的图片、外部链接等不会携带它。
- App UUID 使用相同的系统密钥保护器，数据库中只有本地引用和密文；更换后保留旧引用对应的密文供固定操作核对，常规查询不返回秘密或秘密片段。观察、配置代次与逐项意图／报告保存在独立表中，不随读取失败清除。
- 界面页面启用 sandbox 与 context isolation，禁用 Node 集成与 webview，使用严格 CSP；不允许页面导航到其他地址或打开新窗口，拒绝所有权限请求。界面只能调用少量具名操作，主进程校验调用页面（仅主窗口主框架中的应用页面）与参数，不提供任意网址、SQL 或文件访问。
- 应用只运行一个实例。

## 开发

需要 Node.js 24 LTS 与 npm（版本见 `.nvmrc`；`.npmrc` 启用了 `engine-strict`）。

```bash
npm ci            # 安装锁定依赖
npm run dev       # 开发模式（热更新）
npm run build     # 构建到 out/
npm start         # 运行构建产物
npm run typecheck # 主进程、preload、共享代码与界面的类型检查
npm test          # Vitest，运行在 Electron 自带的 Node 中，与应用使用同一 SQLite 驱动
```

代码结构：

| 位置 | 职责 |
| --- | --- |
| `src/shared/` | 主进程与界面共享的数据类型、读取结果与具名接口 |
| `src/main/forum/` | 论坛请求（限定来源与可携带饼干的来源、解压、体积与超时）、JSON 规范化与正文安全解析 |
| `src/main/identity/` | 饼干导入解析、系统密钥保护适配、用途选择与浏览身份解析 |
| `src/main/storage/` | 数据库 worker、迁移、覆盖计算、饼干密文与用途选择 |
| `src/main/reading/` | 前台／后台请求通道、读取与缓存回退、末尾有限探测 |
| `src/main/subscriptions/` | App JSON／网页 HTML 适配、UUID 保护、固定对象的观察与逐项写入／回读恢复 |
| `src/main/images/` | 图片请求（限定来源、无凭据、不跟随重定向）、按文件内容识别格式、受管图片文件与保存 |
| `src/main/content/` | 收藏、历史清理、普通缓存额度与清理、离线副本的后台保存／更新与取消 |
| `src/main/search/` | 按窗口隔离的搜索会话、取消、分批重建与显式后台取串；索引与事务投影位于 `src/main/storage/search*.ts` |
| `src/main/drafts/` | 草稿保存与删除、附图受管副本及其保护与回收、新编辑的发言饼干选择（串内选择优先于默认） |
| `src/main/ipc.ts`、`src/preload/` | 具名 IPC 与调用方校验 |
| `src/renderer/` | React 界面 |
