# 导出文件是裁剪过的数据库快照，导入整体覆盖

换电脑或重装时，用户要把个人记录、草稿与偏好带到另一台汐岛。导出文件采用本机数据库的快照：复制后去掉普通缓存、搜索索引、使用统计实例与本机秘密密文，再与草稿附图（以及用户选择时的离线副本图片）和清单一起打包。导入沿用恢复升级前备份的暂存、重启、换库流程，旧结构由现有迁移链升级到当前结构；被替换的数据另存为导入前数据。饼干凭据与 App UUID 只在用户勾选时随文件带走，此时整个文件以导出口令加密。目标机上找不回来的数据不随覆盖丢失：饼干凭据、App UUID 与官网账号会话、离线副本、草稿保留并追加到导入结果，其余个人数据被替换。

这样做是因为导入只需覆盖，不需要合并；快照让每类数据不必各写一套字段白名单与导入逻辑，旧版文件的兼容也直接复用迁移链，而不是另维护一套格式转换器。

## Considered Options

- **逐类逻辑记录（JSON 字段白名单）**：文件可读、日后可做合并，但每类数据都要单独定义导出导入和版本转换，等于提前完成暂停中的多端同步的合并规则；覆盖导入用不上这些好处。
- **整库原样复制**：最简单，但会带上普通缓存、另一台机器解不开的秘密密文和使用统计实例，后者会让两台机器共用一个统计身份。

## Consequences

- 迁移链不能截断或合并到导出功能首个发布结构版本之前；任一旧版导出文件都必须能从它的结构版本迁移到当前版本。
- 迁移须能处理裁剪过的库：普通缓存表为空、秘密表为空或被替换。
- 较旧版本打开较新导出文件时拒绝并提示升级，不尝试只读或部分导入，与 [ADR 0003](./0003-downgrade-restores-pre-upgrade-backup.md) 一致。
- 导出文件不适合人工阅读，也不能直接用于合并；将来若恢复多端同步，需另定交换格式。
- 目标机保留的饼干凭据改用不与文件冲突的新编号，引用它们的草稿随之改写，使导入的引用不会落到另一块饼干上；文件与目标机凭据相同的饼干只留文件那一份。两边都有同一串的离线副本时留较晚更新的那份。
- 每张表、每个设置键与每个本机数据目录都必须归入一类：随文件覆盖、目标机保留、目标机保留并追加、秘密、不导出。漏归类由类型检查或测试拒绝，新功能新增数据时必须决定归类。导出功能首次发布时提交一份导出文件样本，之后的迁移都须在测试中能升级它。
- 导入在暂存阶段把文件迁移到当前结构，换库后不再生成升级前备份；原有升级前备份在导入生效时删除，否则降级后恢复它会悄悄撤销导入。导入之前的状态只由导入前数据保存，且只留最近一份。导入后再降级按没有可用备份的只读路径处理。
