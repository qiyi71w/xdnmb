# 访问记录保护主帖文字与回复数，不保护图片和其他页

浏览历史本来就是个人记录，不随普通缓存清理，但它引用的主帖和回复数是普通缓存，会被容量淘汰或手动清理，于是历史行只剩串号和标题，历史内的关键词筛选也无从判断正文。现在改为：每条访问记录把该串的主帖文字和最近一次回复数纳入受保护内容，和离线副本、草稿同一类，不占普通缓存额度，“清理普通缓存”也不删除；删除访问记录或清空历史时解除这层保护，内容转为普通缓存并立即检查额度，仍被离线副本、草稿或当前阅读保护的照旧。

每条只有几 KB，万条级历史也在几十 MB 内；缩略图和其余页体积大一个量级，且列表已允许缩略图缺失、整串阅读由离线副本负责，所以不纳入。

## Considered Options

- **不改保护，只按已知字段筛选**：保留为存量行的兜底，但用得越久，可判断的行越少。
- **连带保护主帖缩略图**：图片文件的空间代价不成比例。
- **保护该串本机已有的全部页**：等于把历史变成轻量离线副本，和离线的分工重叠。
- **清理缓存时一并清掉历史**：违背历史保留到手动删除的产品约定。

## Consequences

- 需要一次 schema 迁移，扩大受保护的范围；旧版汐岛打开新库时只读，按 [ADR 0003](./0003-downgrade-restores-pre-upgrade-backup.md) 处理降级。
- 迁移前已被淘汰的主帖不回填、不联网补取；下次打开该串取得主帖后才受保护，在那之前筛选只按串号和标题判断，并说明数量。
- 受保护的主帖会长期留在本机搜索索引中，搜索页能持续搜到访问过的串的主帖。
- 缓存上限设得很小、历史又很多时，可能出现“受保护的内容使占用无法回到上限以内”。
