# 提醒以论坛回复数为基线，不做从第 1 页起的覆盖证明

论坛订阅接口不提供回复数，串页 `/api/thread`、`/api/po` 的 `ReplyCount` 是唯一的轻量更新信号；它包含已删除的回复，分页也按它切分。提醒改为以最近一次确认的回复数为基线：全串更新与 PO 追更只比较各自模式第 1 页的 `ReplyCount`（每串每次检查一个请求），引用我的发言只读基线所在页到当前末页之间的新增页，不再从第 1 页连续读取以证明覆盖完整，也不在编号序列变化时回退重扫。这样做是为了让后台定时检查的请求量与串长度无关、只随新增内容增长，降低触发论坛限流或被视为异常抓取的风险。

## Considered Options

- **从第 1 页起逐页扫描并用连续编号证明覆盖**（此前实现）：能发现计数无法反映的变化，但长串首次检查及序列变化后的重扫需要按页数发出请求，是最可能触发限流的路径。
- **逐条列出全串新回复**：需要读出全部新增页；全串更新与 PO 追更只显示计数，仅引用匹配需要正文。

## Consequences

- 提醒结果是“回复数增长了多少”，不是逐条事件；计数包含之后被删除的回复。
- 回复数在读取间隔内若被论坛以其他方式修正（未观察到），提醒可能多计或少计；读取失败、缺页和未能核实的被引发言仍作为覆盖问题单独提示，不当作没有新回复。
